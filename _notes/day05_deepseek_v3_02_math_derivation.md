## PART A. DeepSeekMoE 게이트 (식 12–15)

```
h'_t = u_t + Σ_{i=1}^{N_s} FFN_i^(s)(u_t) + Σ_{i=1}^{N_r} g_{i,t} · FFN_i^(r)(u_t)   ... (12)
g_{i,t} = g'_{i,t} / Σ_{j=1}^{N_r} g'_{j,t}                                          ... (13)
g'_{i,t} = s_{i,t}  if  s_{i,t} ∈ Topk({s_{j,t}}, K_r)   else 0                       ... (14)
s_{i,t} = Sigmoid(u_tᵀ e_i)                                                          ... (15)
```

**V2 → V3 변경점 2개:**
1. **`s = Sigmoid(uᵀe)`** (V2는 `Softmax_i(uᵀe_i)`). 시그모이드는 **토큰별 독립** 점수라 top-k 선택이 다른 토큰과 **경쟁하지 않는다**.
2. 선택된 점수를 **재정규화**(식 13의 `Σ g'`)하고 `route_scale=2.5`를 곱한다(코드에서 확인).

> Day 04의 V2 게이트(소프트맥스 + top-K)와 대비하면, V3는 **"선택은 독립 점수로, 크기는 부분합으로 재정규화"** 라는 2단 구조다. 이 분리가 §A.2의 "왜곡 0"을 가능케 한다.

## PART A.2 Auxiliary-Loss-Free 균형 (식 16) — 오늘의 핵심

```
g'_{i,t} = s_{i,t}  if  (s_{i,t} + b_i) ∈ Topk({s_{j,t} + b_j}, K_r)   else 0        ... (16)
```

**읽는 법:** `b`가 등장하는 곳은 **오직 `Topk`의 판정식**이다. 분기에서 **돌려주는 값은 `s_{i,t}`** — 즉 `b`는 **선택 집합을 바꿀 뿐, 선택된 항의 크기를 바꾸지 않는다.**

### (a) 게이트 왜곡이 정확히 0인 이유

선택 집합 `S_t = argtopk_K(s_{:,t} + b)` 라 하고, 최종 가중치를 보자.

```
g_{i,t} = 1[i ∈ S_t] · s_{i,t} / Σ_{j∈S_t} s_{j,t}
```

`b`는 **집합 S_t를 통해서만** 결과에 영향을 준다. `b`를 상수 `c`만큼 **모두** 더하면 `S_t`가 변하지 않으므로 출력도 변하지 않는다 → **`b`의 절대값이 아니라 상대적 배열만이 의미**를 갖는다. 게다가 전문가 `i`가 뽑히기만 하면 그 가중치는 **`s_{i,t}` 그대로**다(코드: `weights = original_scores.gather(...)`).

- auxiliary **loss** 방식: `L_total = L_LM + α·L_Bal` → 그래디언트로 `e_i`(centroid) 자체를 밀어 **점수가 변한다 → 왜곡 O**.
- auxiliary-**loss-free** 방식: 목적함수에 항이 없다. `b`를 **규칙으로만** 움직인다 → **점수는 학습으로도, 규칙으로도 변하지 않는다 → 왜곡 0**.

### (b) 그런데 왜 균형은 잡히는가 (제어기 해석)

매 스텝 배치 부하 `load_i`를 관측하고:

```
if load_i > mean(load):  b_i ← b_i - γ        # 과부하 → 선택될 확률을 낮춘다
if load_i < mean(load):  b_i ← b_i + γ        # 부족   → 선택될 확률을 높인다
```

- 이는 **적분기(integrator)를 가진 음의 피드백 루프**다: `b`가 누적되면서 `S_t`를 밀어 부하를 평준화한다. 그래서 **목적함수에 항을 추가하지 않고도** 균형에 도달한다.
- `sign(·)`만 쓰는 **고정 스텝 적분기**라서, 해에 도달해도 **정지하지 않고 계속 ±γ씩 넘나든다** → 실습 [SIM]에서 관측한 **진폭 ∝ γ인 극한순환**. (γ=0.001/0.002/0.005/0.01 → 잔여 불균형 6.1/14.2/30.5/74.6%로 **단조 증가**, 1200스텝=3000스텝)
- 따라서 `γ`는 **수렴 속도** 손잡이가 아니라 **진동 진폭** 손잡이다.

### (c) 손잡이 스케줄 (§4.2) — 왜 후반에 끄나

```
γ = 0.001  (첫 14.3T 토큰)      → 균형을 잡는 구간
γ = 0.0    (마지막 500B 토큰)   → b를 동결
```

- 균형이 이미 달성된 뒤에는 **`b`를 흔들 이유가 없다**. 동결하면 (i) 라우팅 분포가 늦은 학습에서 **안정**되고, (ii) 전문가들이 **고정된 선호 위에서 전문화**를 마무리할 수 있다.
- 실습 대조: bias를 계속 갱신하면 진폭 γ만큼 **영원히 진동**한다 → 후반 동결은 "성능을 위해 진동을 멈추는" 선택으로 읽으면 정확하다.

### (d) 보조 시퀀스 균형 손실 (식 17–20) — 안전망

```
L_Bal = α Σ_{i=1}^{N_r} f_i P_i                                                       ... (17)
f_i   = N_r/(K_r T) · Σ_{t=1}^{T} 1( s_{i,t} ∈ Topk({s_{j,t}}, K_r) )                 ... (18)
s'_{i,t} = s_{i,t} / Σ_{j=1}^{N_r} s_{j,t}                                            ... (19)
P_i   = (1/T) Σ_{t=1}^{T} s'_{i,t}                                                    ... (20)
```

- `f_i` = **토큰 비중**, `P_i` = **확률 질량 비중** → 둘의 곱을 합: "부하 비중 × 확률 비중"이 고르면 작아지는 고전적 balance loss.
- **`α = 0.0001`** — 사실상 **꺼진 수준**. 목적은 성능이 아니라 **한 시퀀스 안의 극단 불균형 방지**(논문의 표현: *"just to avoid extreme imbalance within any single sequence"*).
- 왜 완전히 지우지 않나? `b`는 **배치 전체**를 보고 움직이므로, **개별 시퀀스** 수준의 극단 편중은 잡지 못한다 → 그 구멍만 **극소 α**로 막는다.

### (e) scope가 성능을 바꾼다 (§4.5.3, 1B/3B 검증 손실)

| 모델 | sequence-wise aux | aux-loss-free | batch-wise aux |
|---|---|---|---|
| 1B MoE | 2.258 | **2.253** | **2.253** |
| 3B MoE | 2.085 | **2.080** | **2.080** |

- **aux-loss-free ≈ batch-wise aux** (동일), **sequence-wise는 열등**.
- 즉 이득의 원인은 "loss가 없어서"가 아니라 **제약의 범위가 batch로 넓어져서**다:
  - sequence-wise = *"각 시퀀스 안에서도 고르게"* → 도메인 특화를 **금지**(코드 시퀀스도 수학 전문가를 쓸 확률을 강제로 고르게 만듦).
  - batch-wise = *"배치 전체로 고르게"* → 시퀀스별로는 치우쳐도 됨 → **전문가가 도메인별로 전문화** → 성능↑ (§4.5.3 Figure 9: aux-loss-free가 전 층에서 전문화가 더 큼).
- **인과 사슬:** 제약 범위 확대 → 시퀀스 내 자유도↑ → 도메인 전문화↑ → 검증 손실↓.

## PART B. Multi-Token Prediction (식 21–25)

```
h'_i^k   = M_k [ RMSNorm(h_i^{k-1}) ; RMSNorm(Emb(t_{i+k})) ]                        ... (21)
h^k_{1:T-k} = TRM_k(h'^k_{1:T-k})                                                    ... (22)
P^k_{i+k+1} = OutHead(h_i^k)                                                          ... (23)
L_MTP^k  = CE(P^k_{2+k:T+1}, t_{2+k:T+1}) = -(1/T) Σ_{i=2+k}^{T+1} log P^k_i[t_i]     ... (24)
L_MTP    = (λ/D) Σ_{k=1}^{D} L_MTP^k                                                  ... (25)
```

### B.1 차원과 구조

- `M_k ∈ R^{d × 2d}`: **`2d` → `d`** — 두 갈래(`h^{k-1}`, `Emb(t_{i+k})`)를 **이어붙여(concat)** 접는 융합 행렬. 왜 concat인가: 두 벡터의 **스케일·의미가 다르므로** 각각 `RMSNorm` 후 **더하지 않고 이어붙여** 학습된 혼합을 만든다.
- `k=1`이면 `h_i^0`는 **본체 마지막 표현**, 그리고 입력은 **`t_{i+1}`의 임베딩** → 출력은 **`t_{i+2}`** 예측.
- **순차(sequential) chain** — Gloeckle et al.이 **독립 병렬 헤드**로 `D`개를 예측한 것과 달리, V3는 `h^{k-1}`을 입력으로 받아 **깊이마다 causal chain을 유지**한다. `D=1`이라 실질적으로는 "본체 표현 + 다음 토큰 임베딩 → 다다음 토큰"의 한 단계.

### B.2 왜 공유 임베딩·헤드인가

- `Emb(·)`, `OutHead(·)`를 본체와 **공유** → 추가 파라미터는 `M_k` + `TRM_k`뿐.
- DualPipe가 **얕은 층(임베딩)과 깊은 층(head)을 같은 PP 랭크**에 배치 → **물리적으로도 파라미터·그래디언트를 공유**해 메모리 절약.
- 실습 검증: λ=0.1에서 공유 **embed 2.43e-01 · head 5.73e+00**, MTP **proj 1.02e+01** — 셋 다 `≠0` → **detach된 부가 헤드가 아니다**.

### B.3 "미래를 훔쳐보지 않는다"의 증명(실습)

`D=1` 모듈이 읽는 창은 `ids[1:T+1]`(=`t_{i+1}`들)이다. 따라서:

- 창 **안** 교란 → 출력 변화 **3.761e+00** (의존 O)
- 창 **밖**(`ids[T+1]`, 즉 `t_{i+2}` 위치) 교란 → **0.000e+00** (정답 유출 X)

### B.4 `λ` 스케줄 (§4.2)

```
λ = 0.3  (첫 10T 토큰)      → 초반: 다중 토큰 신호를 강하게  (표현이 미래를 미리 계획하도록)
λ = 0.1  (나머지 4.8T)      → 후반: 본체 목표(다음 토큰) 간섭 최소화
D = 1
```

`L_total = L_main + λ·L_MTP` 형태에서 **λ는 "보조 목표의 비중"** 이다. 초반에 크게, 후반에 작게 — aux-loss-free의 `γ` 스케줄과 **정반대 방향**인데, 이유가 다르다: `γ`는 *제어를 멈추는* 것이고 `λ`는 *보조 신호를 줄이는* 것이다.

### B.5 추론 경로에서는 제외된다

- MTP는 **본체 성능 향상**이 주목적 → 추론 **코드 경로**는 모듈을 사용하지 않는다(공식 추론 코드에 MTP 부재 = PART D).
- 다만 **공개 가중치에는 MTP 모듈(layer 61)이 포함**되어 있고, `enorm`/`hnorm`은 `README_WEIGHTS.md`에 *"speculative decoding에 필요한 RMSNorm 파라미터"* 로 명시된다. 즉 "버린다"는 **코드 경로의 선택**이지, 가중치에서의 삭제가 아니다.
- 별도로 붙이면 **speculative decoding**에 재활용 가능(논문 §2.2).

## PART C. FP8 혼합정밀도 — 스케일을 어디에, 누산을 어떻게

### C.1 양자화/역양자화

블록별 스케일 `s`에 대해:

```
x = s_x ⊙ x_q        (활성, 1×128 타일)
w = s_w ⊙ w_q        (가중치, 128×128 블록)
Y = Σ_k (s_x ⊙ x_q)·(s_w ⊙ w_q)   →  스케일을 밖으로 빼면  Y = s_x s_w Σ_k x_q w_q
```

- **스케일 정의(코드 `kernel.py`와 동일):** `s = amax/448` (448 = E4M3 최대값), `amax`는 `1e-4`로 클램프.
- **`s`를 2의 거듭제곱으로 반올림**하는 옵션(`scale_fmt="ue8m0"`, `s → 2^ceil(log2 s)`)을 특정 텐서에만 쓴다(§3.3.3).

### C.2 왜 세분화가 필요한가 (아웃라이어)

per-tensor 양자화: `s` 하나가 **텐서 최대값**에 맞춰져, 작은 값들이 격자 간격에 뭉개진다(아웃라이어가 스케일을 독점).

- 실습 [FAKEQ] (가중치 1채널 ×150, 활성 4채널 ×80 아웃라이어 주입):
  | 방식 | 상대오차 |
  |---|---|
  | per-tensor (E4M3) | 3.8795e-02 |
  | **block 128×128 / 1×128 (E4M3)** | **1.7051e-02** (2.3×) |
  | block + E5M2 | 3.0361e-02 |
- 세분화하면 **그룹 내 최대값**이 스케일이 되어 아웃라이어 영향이 국소화된다.

### C.3 왜 "모두 E4M3"가 가능한가

선행연구: Fprop만 E4M3, Dgrad·Wgrad는 **E5M2**(범위 필요). V3: **전부 E4M3**(가수 1비트 더).

- E4M3는 **가수 3비트**로 더 정밀하지만 **지수 4비트**로 범위가 좁다 → 원래는 역전파(그래디언트)에 부적합.
- **1×128 / 128×128로 쪼개면** 좁은 그룹이 **지수 비트를 공유**하게 되어 동적범위 문제가 완화된다 → 범위를 위해 가수를 포기(E5M2)할 필요가 없어진다.
- 실습 대조: 같은 블록에서 **E5M2로 바꾸면 개선분이 거의 되돌아간다**(1.71e-02 → 3.04e-02) → 가수 1비트가 곧 정밀도.

### C.4 누산 정밀도와 승격(promotion)

- H800 텐서코어의 FP8 GEMM 누산은 **약 14비트**만 유지 → `K`가 큰 실제 학습에서 치명적.
  - 논문 실측: `K=4096` 랜덤행렬 GEMM에서 **최대 상대오차 ~2%**.
- 해법: **`N_C = 128` 원소 MMA(= WGMMA 4개)마다** 부분합을 **CUDA 코어 FP32 레지스터로 승격**해 완전정밀 누산. 동시에 그룹별(**K방향**) 스케일도 CUDA 코어에서 곱해 역양자화(추가 비용 최소).

```
Tensor Core:  MMA × 128  → [부분합]
CUDA Core:    FP32 누산 + (그룹 스케일 곱)  → 반복 (N_C=128 간격)
```

### C.5 오차 예산 (논문 수치)

| 항목 | 값 | 출처 |
|---|---|---|
| BF16 대비 **상대 손실오차** | **< 0.25%** (16B/1.33T, ~230B/~0.9T 토큰) | §3.3, §B.1 |
| 승격 없을 때 GEMM 상대오차 | ~2% (`K=4096`) | §3.3.2 |
| **활성 그래디언트(Dgrad) 블록 양자화** | **16B MoE · ~300B 토큰에서 발산** | §B.2 |

**§B.2의 교훈:** 활성 그래디언트는 **토큰 간 불균형이 커서 토큰-상관 아웃라이어**가 생긴다 → 128×128 블록으로는 그 아웃라이어를 담지 못해 **발산**. 그래서 활성(과 그 그래디언트)은 **1×128 타일**로 자른다. 즉 **"가중치=블록, 활성=타일"은 취향이 아니라 수치적 필연**이다.

### C.6 정밀도 정책 표 (무엇을 FP8로, 무엇을 남기는가)

| 대상 | 정밀도 | 이유 |
|---|---|---|
| Fprop/Dgrad/Wgrad GEMM | **FP8** | 연산 밀도 최대 → 이득 최대 |
| MoE up-proj 입력(dispatch 전) | **FP8** (+2^k 스케일) | **통신량** 절감 |
| SwiGLU 입력(cache) | FP8 (재계산) | 활성 메모리 절감 |
| attention 뒤 Linear 입력 | **E5M6** (+128×1, 2^k 스케일) | 어텐션 역전파에 재사용 → 민감 |
| combine(dispatch/combine) | **BF16** 유지 | 파이프라인 핵심부 정밀도 |
| embedding · output head · **MoE gating** · norm · attention | **BF16/FP32** | 저정밀 민감(게이팅!) |
| AdamW 1·2차 모멘트 | **BF16** | 메모리 ↓, 성능 손실 무관측 |
| master weight · weight grad | **FP32** | 안정성 |

> 주목: **MoE gating은 FP8로 내리지 않는다.** 라우팅은 이산적(top-k)이라 작은 오차가 **다른 전문가 선택**으로 증폭된다 — Day 05 전체에서 가장 중요한 정밀도 경계다.

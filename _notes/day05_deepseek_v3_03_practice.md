## 2. 결과 읽기

### (1) 균형 — "누가 더 균형 잡나"가 아니라 "무엇을 대가로 내나"
- 셋 다 `maxvio` 700%에서 출발(전문가 인기도가 멱법칙으로 편향) → 균형 전략이 없으면 그대로 유지.
- **aux-loss**: 700% → **1.7%**. 가장 잘 잡는다. 그러나 **게이트 점수 왜곡 6.071e-02**를 지불한다.
  부하 편차에 비례해 점수를 밀어내므로, 균형이 좋을수록 점수는 원래 값에서 멀어진다.
- **aux-loss-free**: 700% → **6.1%**. 균형은 조금 덜 잡히지만 **점수 왜곡이 정확히 0**.
  bias `b_i`는 **선택(top-k)에만** 더해지고 가중치에는 쓰이지 않으므로, 왜곡 0은 **구조적으로 보장**된다.
  → 시뮬레이션이 발견한 것은 "0"이 아니라 **"그런데도 균형이 잡힌다"**는 쪽이다.
- **로드 엔트로피**: top-k only 2.489 (편향) → 두 전략 모두 **4.159** (≈ `ln 64 = 4.159`).
  즉 두 방법 모두 **이론 최대 균등**에 도달한다. 남은 차이는 *균형의 정도*가 아니라 **비용의 종류**다.

### (1b) γ 민감도 — sign 기반 bias 갱신은 극한순환이 된다
동일 조건에서 γ만 바꾸고 3000 스텝까지 돌린 결과 (`runs/balance_gamma_sweep.json`):

| γ | aux-loss-free maxvio | aux-loss maxvio (참고) | aux 왜곡 |
|---|---|---|---|
| 0.001 | **6.1%** | 1.8% | 6.071e-02 |
| 0.002 | **14.2%** | 1.8% | 6.071e-02 |
| 0.005 | **30.5%** | 1.8% | 6.071e-02 |
| 0.01 | **74.6%** | 1.8% | 6.071e-02 |

- 잔여 불균형이 **γ에 단조 증가**하고, **1200 스텝과 3000 스텝의 값이 완전히 동일**하다.
  → 0으로 수렴하는 게 아니라 **진폭 ∝ γ인 극한순환(limit cycle)** 에 들어간다.
  `b_i ← b_i + γ·sign(e_i)` 는 **고정 스텝 적분기**라, γ가 크면 매 스텝 반대편으로 넘어가 왕복한다.
- 그래서 γ는 "빠른 수렴"을 위한 손잡이가 아니라 **"진동 진폭"을 정하는 손잡이**다.
  (논문이 γ를 매우 작게 두는 이유 — 아래 `02_수식유도.md`에서 값 대조)
- 반면 aux-loss 쪽은 γ와 무관하다(α로 제어). 즉 **두 방법은 손잡이의 종류 자체가 다르다**.

### (2) MTP — 창(window)이 정확히 t+1 하나만 연다
- 창 **안** 임베딩을 교란 → 출력 변화 **3.761e+00** (의존한다).
- 창 **밖**(t+2 위치)만 교란 → 출력 변화 **정확히 0**. → **미래 토큰을 훔쳐보지 않는다**.
- 그래디언트: 공유 **embed 2.43e-01**, 공유 **head 5.73e+00**, MTP **proj 1.02e+01** — 전부 ≠ 0.
  → MTP 모듈은 detach된 부가 헤드가 아니라 **공유 임베딩·헤드와 함께 학습**된다.
- `λ=0.1` 에서 `loss = 0.5760` → λ가 손실 기여를 선형 축소(본체 CE에 대한 보조 비중).

### (3) FP8 — 블록 스케일이 없으면 아웃라이어가 전체를 망친다
합성 텐서에 채널 아웃라이어를 심어둔 상태(가중치 한 채널 ×150, 활성 4개 채널 ×80)에서:

| 방식 | 상대 오차 |
|---|---|
| per-tensor (E4M3) | 3.8795e-02 |
| **block 128×128 / 1×128 (E4M3)** | **1.7051e-02** (2.3× 개선) |
| block이지만 E5M2 (가수 2bit) | 3.0361e-02 |

- **스케일을 어디서 잡는가**가 형식보다 중요하다: per-tensor는 아웃라이어 하나가 스케일을 독점해 나머지 값을 뭉갠다.
- 형식 선택: 같은 블록에서 **가수 1bit 차이(E4M3 → E5M2)가 개선분을 거의 되돌린다**(1.71e-02 → 3.04e-02).
  범위가 필요해 E5M2를 쓸 수는 있지만 **정밀도를 지불**한다 — 그래서 가중치·활성은 E4M3.
- [FAKEQ] 한계: 실제 FP8 텐서코어 누산(FP32)과 고정밀 승격(promotion)은 재현하지 않았다.
  여기서 측정한 것은 **격자 근사 오차**까지다.

### (4) 회계 — 설정만으로 headline이 재현된다 [EXACT]
| | 계산값 | 논문 headline | 차이 |
|---|---|---|---|
| V2 총 | **235.7B** | 236B | −0.13% |
| V2 활성 | **21.3B** | 21B | +1.4% |
| V3 총 | **671.0B** | 671B | −0.0% |
| V3 활성 | **37.6B** | 37B | +1.6% |

- 차이의 원인(추정): MLA 파라미터 세부(q/kv norm, wq_b·wkv_b 정확한 shape), MTP 모듈 파라미터 미포함,
  임베딩·헤드 공유 여부. **1%대면 config 해석이 맞다**고 보는 게 합리적이다.
- MoE 층 수: V2 **59**(60−1), V3 **58**(61−3) — 앞쪽 dense 층 수가 다르다.
- 조합 수: `C(160,6) ≈ 2.12×10^10` → `C(256,8) ≈ 4.10×10^14` = **약 19,300배**.
  V3는 전문가를 늘리고 top-k도 늘려 **조합 공간을 4자릿수 이상 확장**했다.

## 3. 손으로 따라하기

```python
# (1) bias 갱신 한 줄이 전부다
err  = (load.mean() - load) / load.mean()   # 과부하 전문가는 err < 0
bias = bias + gamma * err.sign()            # 선택 로짓에만 더함 → 가중치엔 안 들어감
sel  = (scores + bias).topk(k).indices

# (1b) γ만 바꿔 3000 스텝: 6.1% / 14.2% / 30.5% / 74.6%  ← 단조 증가 = 극한순환
#      스텝을 1200 → 3000 으로 늘려도 값이 같다(수렴이 아니라 진동)

# (2) 룩어헤드 검사는 '창 밖'을 건드려야 의미가 있다
#     읽는 창 = ids[1:T+1]  →  창 밖 ids[T+1] 를 교란해야 0 이 나온다

# (3) 블록 스케일
scale = 448.0 / blk.abs().amax(dim=-1, keepdim=True)   # 128개 원소마다 스케일
q     = round_to_mantissa(blk * scale, bits=3) / scale # E4M3 = 가수 3bit
```

## 4. 실패/삽질 기록

1. **aux-loss 부호 반전** — 첫 실행에서 `aux-loss` 행이 `700% → 700%`로 **개선이 0**이었다.
   `err = (mean − load)/mean` 은 과부하에서 **음수**인데 `scores −= α·err` 로 써서
   과부하 전문가의 점수를 **오히려 올리고** 있었다. `scores += α·err` 로 수정 → 1.1%.
   → 증상이 "효과 없음"으로 나타나서 눈치채기 어렵다. **부호는 결과로 검증할 것.**
2. **룩어헤드 검사가 창을 침범** — "t+2 임베딩 교란"을 `ids[2:T+2]`로 했더니 모듈이 읽는
   창 `[1:T+1]`과 **겹쳐서** 변화가 3.761e+00으로 나왔다(0이어야 함). 창 **밖**(`ids[T+1]`)만
   건드려야 검사가 성립한다. → **교란 실험은 "무엇을 읽는가"를 먼저 확정하고 창 밖을 건드려야 한다.**
3. **`.detach()`가 학습 그래프를 절단** — 룩어헤드 검사에서 `out`을 detach한 뒤 그 `out`으로 loss를
   계산해 **proj·embed grad가 정확히 0**이 됐다(head만 ≠0이라 겉보기엔 통과처럼 보임).
   `with torch.no_grad():` 로 **검사용 forward만** 감싸고 학습 경로는 그래프를 유지하도록 수정.
   → **"grad가 0"은 버그 신호인데, 일부만 0이면 더 위험**하다(부분 통과).
4. `float(loss)` on requires_grad tensor 경고 → `loss.detach()` (산출물 직렬화 시 필수).

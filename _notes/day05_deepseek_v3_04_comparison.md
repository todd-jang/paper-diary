# 04. 비교표 — V3 **자기 환경 안에서의** true ablation 4종

> **비교 원칙(2026-10-18 확정):** 같은 시스템·같은 도메인(NLP LLM) 안에서 **변수 하나만** 바꾼 표만 "비교"로 인정한다.
> - ✅ V3 논문 §4.5의 ablation(부하균형 on/off · MTP on/off · scope)과 §3.3·§B의 FP8 on/off — **동일 데이터·동일 아키텍처에서 한 변수만 교체**

> - ❌ 도메인 교차 숫자 비교(vision ↔ NLP) — **금지**

## 1. V2 → V3 설정 대조 (계보 맥락, 같은 도메인)

| 항목 | DeepSeek-V2 (236B/21B) | DeepSeek-V3 (671B/37B) | 변경 성격 |
|---|---|---|---|
| layers | 60 | **61** | ↑ |
| dense 층 수 | 1 | **3** | ↑ (MoE 층 59 → **58**) |
| hidden | 5120 | **7168** | ↑ |
| MLA `n_h / d_h` | 128 / 128 | 128 / 128 | 동일 |
| MLA `d_c / d'_c / d_h^R` | 512 / 1536 / 64 | 512 / 1536 / 64 | 동일 |
| 게이트 점수 함수 | **softmax** | **sigmoid** | **변경** |
| gating 재정규화 + `route_scale` | — | Σg' 정규화 × **2.5** | **신규** |
| 공유 전문가 `N_s` | 2 | **1** | ↓ |
| 라우팅 전문가 `N_r` | 160 | **256** | ↑ |
| 활성 라우팅 `K_r` | 6 | **8** | ↑ |
| 전문가 intermediate | 1536 | **2048** | ↑ |
| 노드 제한 라우팅 | device-limited | **그룹 8 · 최대 4노드 (`M=4`)** | 구체화 |
| **부하 균형** | aux loss | **aux-loss-free (bias)** | **변경** |
| **MTP** | 없음 | **`D=1`, λ=0.3 → 0.1** | **신규** |
| **FP8 학습** | 없음(BF16) | **FP8 + 128×128 / 1×128 + 승격** | **신규** |
| 학습 토큰 | 8.1T | **14.8T** | ↑ |

**읽는 법:** V3는 MLA를 **그대로** 두고, MoE 크기를 키운 뒤(256×8), **게이트·균형·목표·정밀도** 네 곳만 새로 설계했다. 즉 V3의 기여는 "더 큰 모델"이 아니라 **"더 큰 모델을 굴리는 방법"** 이다.

## 3. ✅ True ablation ② — MTP: **on/off** (논문 Table 4)

동일 데이터 · 동일 아키텍처 · **1-depth MTP 모듈 부착 여부만** 교체. 추론 시 MTP를 버리므로 **비교 모델의 추론 비용은 정확히 동일**하다(논문 명시).

| Benchmark (Metric) | Shots | Small MoE<br>Baseline | Small MoE<br>**w/ MTP** | Large MoE<br>Baseline | Large MoE<br>**w/ MTP** |
|---|---|---|---|---|---|
| 총/활성 (inference) | — | 15.7B / 2.4B | 동일 | 228.7B / 20.9B | 동일 |
| 학습 토큰 | — | 1.33T | 1.33T | 540B | 540B |
| Pile-test (BPB) ↓ | — | 0.729 | 0.729 | 0.658 | **0.657** |
| BBH (EM) | 3 | 39.0 | **41.4** | 70.0 | **70.7** |
| MMLU (EM) | 5 | 50.0 | **53.3** | **67.5** | 66.6 |
| DROP (F1) | 1 | 39.2 | **41.3** | 68.5 | **70.6** |
| TriviaQA (EM) | 5 | 56.9 | **57.7** | 67.0 | **67.3** |
| NaturalQuestions (EM) | 5 | **22.7** | 22.3 | 27.2 | **28.5** |
| HumanEval (Pass@1) | 0 | 20.7 | **26.8** | 44.5 | **53.7** |

**관찰 (지표값 20칸 기준):**
- **20칸 중 17칸 개선 · 1칸 동일(`Pile 소형` 0.729=0.729) · 2칸 하락(`MMLU 대형` 67.5→66.6, `NQ 소형` 22.7→22.3).**

## 4. ✅ True ablation ③ — 균형의 **scope**: sequence-wise vs batch-wise (논문 §4.5.3)

같은 크기·같은 데이터에서 **균형 제약의 범위**만 바꾼 검증 손실(낮을수록 좋음).

| 모델 | sequence-wise aux | **aux-loss-free** | batch-wise aux |
|---|---|---|---|
| 1B MoE | 2.258 | **2.253** | **2.253** |
| 3B MoE | 2.085 | **2.080** | **2.080** |

**관찰 (핵심):**
- **`aux-loss-free ≡ batch-wise aux`** (1B·3B **모두 동일값**). 즉 이득의 원인은 "loss가 없음"이 아니라 **"제약이 시퀀스가 아니라 배치에 걸림"** 이다.
- sequence-wise는 **열등** — 시퀀스 내 균형을 강제하면 **도메인 전문화가 막힌다**(§4.5.3 Figure 9: free 모델이 전 층에서 전문화가 더 큼).
- 인과 사슬: **제약 범위 확대 → 시퀀스 내 자유도↑ → 전문가 전문화↑ → 검증 손실↓**.

## 5. ✅ True ablation ④ — FP8 vs BF16 (논문 §3.3 · §B.1 · §B.2)

| 항목 | BF16 | **FP8 (V3 방식)** | 비고 |
|---|---|---|---|
| 상대 손실오차 (16B/1.33T) | 기준 | **< 0.25%** | 학습 랜덤성 범위 내 |
| 상대 손실오차 (~230B/~0.9T) | 기준 | **< 0.25%** | 두 스케일 모두 |
| GEMM 누산(승격 없음) | FP32 누산 | **K=4096에서 상대오차 ~2%** | H800 텐서코어 ~14bit |
| Dgrad 블록 양자화(128×128) | — | **16B MoE · ~300B 토큰에서 발산** | 활성 그래디언트는 **타일(1×128)** 강제 |
| 스케일 세분화 | — | 활성 **1×128**, 가중치 **128×128** | 아웃라이어 국소화 |
| 승격 간격 | — | **`N_C = 128`**(= WGMMA 4개) | FP32 누산 |
| 텐서 형식 | BF16 | **전부 E4M3** (attention 뒤 Linear만 E5M6) | 선행연구(E5M2 Dgrad)와 차이 |

**실습 [FAKEQ] 격자 오차 대조**(합성 아웃라이어, `v3_demo.py`):

| 방식 | 상대오차 | 해석 |
|---|---|---|
| per-tensor (E4M3) | 3.8795e-02 | 아웃라이어 1개가 스케일 독점 |
| **block 128×128 / 1×128 (E4M3)** | **1.7051e-02** | **2.3× 개선** |
| block + E5M2 | 3.0361e-02 | 가수 1비트 부족 → 개선분 반납 |

> [FAKEQ]는 **양자화 격자 근사**만 측정한다. 실제 FP8 텐서코어 누산·승격은 재현 범위 밖이다(§03의 수치 성격 구분 참조).

## 6. FP8 정밀도 정책 — "무엇을 내리고 무엇을 남기는가"

| 대상 | 정밀도 | 근거 |
|---|---|---|
| Fprop / Dgrad / Wgrad GEMM | **FP8** | 연산 밀도 최대 |
| MoE up-proj 입력(dispatch 전) | FP8 (+2^k 스케일) | **통신량** ↓ |
| SwiGLU 입력(cache) | FP8 + 재계산 | 활성 메모리 ↓ |
| attention 뒤 Linear 입력 | **E5M6** · 128×1 · 2^k 스케일 | 역전파 재사용 → 민감 |
| dispatch/combine(combine) | **BF16** | 파이프라인 핵심부 |
| embedding · output head · **MoE gating** · norm · attention | **BF16/FP32** | **라우팅은 이산적 → 오차 증폭** |
| AdamW 1·2차 모멘트 | BF16 | 메모리 ↓ |
| master weight · weight grad | **FP32** | 안정성 |

**한 줄:** FP8의 경계는 "연산량이 큰 것"이 아니라 **"오차가 이산 선택으로 증폭되는 것(gating)"** 을 기준으로 그어져 있다.

## 10. 한 문장 정리

> **부하 균형은 목적함수에서 `bias`로 옮기고(왜곡 0), 예측 목표는 한 칸 늘리고(MTP), 정밀도는 블록 단위로 국소화한다(FP8)** — V3는 세 곳에서 **"건드리지 않을 것"** 을 정함으로써 671B를 14.8T 토큰 동안 **단 한 번의 rollback 없이** 학습했다.
> 그리고 ablation이 말하는 바는 하나다: **제약을 약화·이관하는 설계가 성능을 *올린다*.**

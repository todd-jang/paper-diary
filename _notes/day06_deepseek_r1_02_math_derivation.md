## PART A. GRPO 목적함수 (식 1) — 가치망을 지우고 그룹 평균을 남긴다

```
J_GRPO(θ) = E[ q~P(Q), {o_i}(i=1..G) ~ π_θold(O|q) ]
            (1/G) Σ_i min( π_θ(o_i|q)/π_θold(o_i|q) · A_i ,
                            clip( π_θ(o_i|q)/π_θold(o_i|q), 1−ε, 1+ε ) · A_i )
            − β · D_KL[ π_θ ‖ π_ref ]                                          ... (1)
```

### A.1 식 (1)의 네 부품

원문은 토큰 단위 확률비를 쓰지만, 위 표기는 논문이 식 (3)과 함께 제시하는 **출력 단위 축약**이다. 어느 쪽이든 부품은 같다.

1. **확률비 `π_θ/π_θold`** — 정책이 갱신되며 이 샘플을 얼마나 더/덜 선호하게 되었는가. `π_θold`는 **롤아웃 시점에 고정**되므로 분모는 상수다.
2. **`A_i`** — 이 출력이 그룹 안에서 얼마나 좋았는가(식 3). **가치망이 들어갈 자리가 정확히 여기다.**
3. **`min(·, clip(·))`** — 확률비가 `[1−ε, 1+ε]`를 벗어나면 그래디언트를 0으로 만든다(PPO 계열의 신뢰영역).
4. **`−β·D_KL[π_θ‖π_ref]`** — 정책이 참조 모델에서 멀어지는 것을 벌한다.

**PPO와의 차이는 ②뿐이다.** PPO는 `A_t = r_t + γV(s_{t+1}) − V(s_t)`로 **학습된 가치망 `V`**를 요구한다. GRPO는 `V`를 **그룹 평균**으로 대체한다. 원문 서술은 "PPO의 훈련 과정을 단순화하고 자원 소비를 줄이기 위해 제안되었다"이며, 이것이 R1이 **critic 네트워크를 학습하지 않는** 이유다.

### A.2 식 (3) — 그룹 정규화의 세 가지 성질

```
A_i = ( r_i − mean({r_1,...,r_G}) ) / std({r_1,...,r_G})                        ... (3)
```

**(a) `Σ_i A_i = 0` 은 항등식이다.** 분자를 그룹 전체에 대해 합하면 `Σ_i (r_i − r̄) = 0`이고 분모 `std`는 `i`에 무관하므로, `Σ_i A_i = 0`이 **항상** 성립한다. 즉 그룹 평균을 빼는 순간 "그룹 평균 보상"이 자동으로 기준선이 된다 — 이것이 가치망의 역할을 **추정 없이** 대체하는 방식이다. `03_실습.md`의 실측값 `0.00e+00`이 이 항등식의 확인이다.

**(b) 난이도 게이팅은 부산물이다.** 그룹이 **전원 정답**(`r_i = 1` ∀i)이거나 **전원 오답**(`r_i = 0` ∀i)이면 `std = 0` → `A_i = 0` → **그래디언트가 정확히 0**이 된다. 질문이 너무 쉽거나 너무 어려우면 학습 신호가 사라지므로, GRPO는 **경계 난이도 질문에 자동으로 집중**한다.

**(c) 두 불변성.** `r → c·r`(스케일)과 `r → r+k`(평행이동)에 대해 `A`는 불변이다 — 전자는 분자·분모가 함께 `c`배, 후자는 `r_i − r̄`가 `k`에 무관. 보상 함수의 **절대 크기와 기준점을 설계할 필요가 없어진다**는 실무적 이득이 있다.

### A.3 식 (2) — k3 추정량의 비음수성

```
D_KL[ π_θ ‖ π_ref ] = π_ref(o_i|q)/π_θ(o_i|q) − log( π_ref(o_i|q)/π_θ(o_i|q) ) − 1    ... (2)
```

`x = π_ref/π_θ > 0`로 두면 식 (2)는 `f(x) = x − log x − 1`이다.

```
f'(x) = 1 − 1/x = 0  ⟺  x = 1
f''(x) = 1/x² > 0    ⟹  x = 1 이 전역 최소
f(1) = 1 − 0 − 1 = 0  ⟹  f(x) ≥ 0
```

**임의의 샘플에서 항상 비음수**이므로, 미니배치 평균으로 근사해도 KL 항이 음수가 되어 **보상을 부풀리는 경로가 없다**. 이것이 `log(π_θ/π_ref)`형 단순 추정량과의 차이다(그 형태는 표본에 따라 음수가 될 수 있다). 또한 `x = 1`(정책이 참조와 동일)에서 정확히 0이다.

## PART B. 규칙 보상 (식 4) — 검증 가능한 것만 보상한다

```
Reward_rule = Reward_acc + Reward_format                                        ... (4)
```

원문은 "정확도 보상과 형식 보상은 **동일 가중(same weight)**으로 결합된다"고 명시한다.

| 항 | 검증 대상 | 원문 근거(§2.2) |
|---|---|---|
| `Reward_acc` | 수학 = **지정 형식(예: box) 안의 최종답** / 코드 = **컴파일러**가 사전 정의된 테스트 케이스에 대해 평가 | "the model is required to provide the final answer in a specified format (e.g., within a box), enabling reliable rule-based verification of correctness" · "a compiler can be utilized to evaluate the model's performance, responses against a suite of predefined test cases, thereby generating objective feedback on correctness" |
| `Reward_format` | `<think>` `</think>` 태그로 사고 과정을 **명시적으로 구획**했는가 | "the model is incentivized to encapsulate its reasoning process within designated tags" |

### B.1 두 항은 **서로 다른 실패 모드**를 잡는다

- `Reward_acc = 0, Reward_format = 1` (오답·형식 유) → **형식만 갖추고 틀린** 출력. 정확도 항이 없으면 이 출력이 보상된다.
- `Reward_acc = 1, Reward_format = 0` (정답·형식 무) → **맞혔지만 파싱할 수 없는** 출력. 형식 항이 없으면 보상은 주어지지만 재현·분석이 불가능하다.

### B.2 `Reward_acc`의 **전제조건**은 파서다

수학 정확도 보상은 "box 안의 값을 꺼내는 것"에서 출발한다. box가 없으면 **정답 여부를 판정할 수 없으므로 `Reward_acc = 0`** 이다. 즉 형식은 장식이 아니라 **정확도 검증의 입력 조건**이다(실측 확인은 `03_실습.md` (2)).

### B.3 형식 보상 **단독 획득 = 해킹 표면**

`Reward_format`은 태그 구조만 보므로, **정답이 0인데도 양의 보상을 얻는 출력이 존재한다**. 이것을 막는 장치가 원문이 말하는 **"빈 사고 블록" 우회 처리**다 — README는 `<think>\n\n</think>`처럼 사고를 비우는 패턴을 경고하며, `"<think>\n"` 강제를 권장한다. 우리 데모는 빈 블록에 **사고 항 0.5를 주지 않는다**(강등). 다만 **구조만 온전한 오답도 여전히 0.5를 받으므로**, 형식 보상은 완전히 봉쇄되지 않는다 — 이 잔여 표면이 PART C에서 모델 기반 보상 **전면 배제**로 이어지는 배경이다.

### B.4 그런데 왜 신경망 RM을 **쓰지 않는가** (§2.2)

원문은 두 이유를 든다. ① **보상 해킹 취약성** — "neural reward models are susceptible to reward hacking during large-scale reinforcement learning". ② **재학습 자원·파이프라인 복잡도** — "retraining such models necessitates substantial computational resources and introduces additional complexity". 배제 범위는 **추론 과제**이며, 일반 도메인은 §3.1이 보상 모델을 쓴다(PART C).

## PART C. 모델 기반 보상 (식 5–6) — 검증할 수 없는 것을 모델에 맡긴다

```
Reward_helpful = RM_helpful( Response A, Response B )                            ... (5)
Reward_safety  = RM_safety( Response )                                           ... (6)
```

| | helpful (식 5) | safety (식 6) |
|---|---|---|
| 판정 형식 | **pairwise** (두 응답 비교) | **point-wise** (단일 응답 라벨) |
| 평가 범위 | **최종 요약만** | **전체 응답**(사고 과정 + 요약) |
| 데이터 | **66,000** 쌍 | **106,000** 프롬프트 |
| 위치 편향 통제 | A/B 순서를 **4회 무작위 교체** 후 평균 | — |
| 채택 임계 | 점수차 `Δ > 1`만 유지 | safe / unsafe |
| 길이 편향 통제 | 채택·거부 응답의 길이 분포를 유사하게 맞춤 | — |

**두 축이 갈리는 이유(§3.1).** 원문은 도움됨에 대해서는 "**the final summary**에만 집중해 평가가 응답의 유용성·관련성에 집중되도록 하고 **근저의 추론 과정과의 간섭을 최소화**한다"고 밝히고, 무해성에 대해서는 "추론 과정과 요약을 **포함한 전체 응답**을 평가해 위험·편향·유해 내용을 식별·완화한다"고 밝힌다. 즉 **의도적으로 다르게 잡았다** — 추론을 보상 대상에서 빼야 추론이 오염되지 않고, 유해성은 추론 단계에서도 나올 수 있으므로 전체를 본다. 아키텍처는 R1과 동일하고 **스칼라 선호 점수를 예측하는 보상 헤드**만 추가한다(helpful: batch 256, lr `6e-6`, 1 에폭, 최대 8,192 토큰).

**일반 보상의 합성(§3.1).** 각 인스턴스는 **안전 데이터셋 또는 도움됨 데이터셋 중 하나**로 분류되고, `Reward_General`은 **해당 데이터셋의 보상**을 그대로 쓴다. 즉 두 RM을 가중 합하는 것이 아니라 **인스턴스별로 선택**한다.

## PART D. 언어 일관성 보상 (식 7) — 검증 불가능한 목표를 규칙으로 근사한다

```
Reward_language = Num(Words_target) / Num(Words)                                ... (7)
```

**적용 방식(§3.2.1).** 혼용 완화를 위해 도입하며, **추론·비추론 데이터 모두**에 적용하고 **최종 보상에 직접 더한다**(`Reward = Reward_... + λ·Reward_language`, λ = 가중). 목표는 가독성 — 원문은 "such alignment results in a slight degradation in the model's performance"라면서도 "**aligns with human preferences, making it more readable**"라고 그 교환을 명시한다.

### D.1 왜 **공짜가 아닌가** — 토큰 예산 고정 하의 자원 재배분

정렬로 언어를 바꾼다고 과제 난이도가 변하지는 않는다. 그런데도 비용이 생기는 이유는 **CoT 길이가 유한**하기 때문이다. 사고 사슬을 `S`개 토큰 슬롯으로 보면, 각 슬롯은 (i) 과제 진행, (ii) 목표언어 표기, (iii) 무의미한 채우기 중 하나로 쓰인다. 언어 제약은 **(i)의 기회를 목표언어 표현으로 강제 전환**하고, 전환된 슬롯의 진행 효율이 원래 언어보다 낮다면 과제 성공률이 떨어진다.

이를 언어 선택률 `q ∈ [0,1]`(목표언어로 추론하는 슬롯 비율)의 문제로 쓰면, 토큰당 진행 확률은 `p(q) = q·p_target + (1−q)·p_foreign`이고 과제 성공률은 `P(Binom(S, p(q)) ≥ m)`이다. 목적함수는

```
maximize_q   R_task(q) + λ · q
```

이며, `λ`가 커질수록 최적 `q*`가 1로 밀려 **혼용률 `1−q*`는 감소하고 `R_task(q*)`는 감소**한다. 즉 **λ는 파레토 곡선 위의 점을 고르는 손잡이**이고, 곡선 자체는 가정 `p_foreign > p_target`에서 유도된다. `03_실습.md` (3)이 이 곡선을 **정책 학습 없이 직접 계산**해 제시한다.

### D.2 B.6이 말하는 것과 말하지 않는 것

원문 부록 B.6은 **DeepSeek-R1-Distill-Qwen-7B**(R1과 동일 cold-start 데이터, RL 중 혼용 발생) 단일 설정의 ablation이다. 결과는 ① LC 보상이 없으면 스텝이 늘수록 언어 일관성이 **점진 악화**, ② 적용하면 **안정 유지**, ③ 벤치마크는 **수학 유사 · 코딩 소폭 저하**. 따라서 "모든 모델·언어·과제에서 같은 비용"은 **주장되지 않는다**.

## PART E. 원문 내 불일치 — §3.2.1의 `ε = 10`

§3.2.1은 "we set the learning rate to 3e-6, the KL coefficient to 0.001, the **GRPO clip ratio ε to 10**"이라고 적는다. 그러나 식 (1)의 clip 구간은 `[1−ε, 1+ε]`이고, 같은 절의 다음 문장이 해석을 제공한다 — "**낮은 값은 다수 토큰의 그래디언트 절단을 낳아 성능을 떨어뜨리고, 높은 값은 학습 불안정을 낳을 수 있다**".

`ε = 10`을 대입하면 하한이 `1 − 10 = −9`가 되어 **확률비 `π_θ/π_θold ≥ 0`에서 하한은 결코 작동하지 않고**, 상한만 `11`로 사실상 **clip이 무력화**된다. 이는 "낮은 값/높은 값"의 논의와 모순되며, PPO·GRPO 계열의 통상값(`0.1 ~ 0.3`)과도 두 자릿수 차이다.

**처리.** 본 문서는 이를 **원기(誤記) 의심**으로 기록하고, R1 하이퍼의 실효값을 확정하지 않는다. 경계 조건은 다음과 같다 — (i) 확인 가능한 것은 **식 (1)의 구조와 §2.1의 `lr 3e-6`·`KL 0.001`** 이고, (ii) `ε`의 실효값은 원문만으로 **결정 불가**이며, (iii) `10`을 문자 그대로 읽으면 clip 항이 비활성화된 GRPO가 된다. `04_비교표.md`에 대조 항목으로 남긴다.

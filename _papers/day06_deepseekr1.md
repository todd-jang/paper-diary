## ✍️ 나의 답변 (본인이 작성 — **논문서술 형식**)

### Q1. R1-Zero에서 R1으로: RL 이후에도 4단계 파이프라인을 둔 이유

**심사식 점검**
(i) **주장의 명료성**: R1 파이프라인은 RL을 버린 것이 아니라, RL이 잘 다루지 못한 가독성·언어 일관성·일반 응답 역량을 SFT와 추가 RL로 보완한 설계입니다.
(ii) **직접 근거**: §2.3의 AIME 수치, §3의 단계별 절차, §3.2.1의 식 (7), 부록 B.6의 LC 보상 제거 ablation을 구분해 인용합니다.
(iii) **경계 조건**: 부록 B.6은 특정 distilled Qwen-7B 실험입니다. 수학 성능은 비슷하고 코딩 성능은 약간 낮아졌다고 보고하므로, LC 보상이 모든 성능을 올린다고 일반화할 수 없습니다.

**답안**

**(a) R1-Zero의 가독성 저하와 언어 혼용.**
논문은 R1-Zero가 영어와 중국어를 한 사고 과정 안에서 섞는 등 가독성과 언어 일관성 문제를 보였다고 설명합니다. §3은 그 배경으로 DeepSeek-V3-Base가 여러 언어, 특히 영어와 중국어로 학습된 점을 듭니다. 따라서 RL이 추론 능력을 끌어냈더라도, 응답 언어와 표현 방식이 사용자의 언어에 맞게 안정적으로 정리된 것은 아니었습니다. §2.3의 AIME 2024 결과는 R1-Zero의 pass@1이 15.6%에서 77.9%로 올라갔고, 64개 응답의 self-consistency 투표(cons@64)에서는 86.7%를 기록했다고 보고합니다. 이는 추론 성능의 큰 향상과 출력 품질 문제가 공존했음을 보여줍니다.

**(b) R1의 4단계와 각 단계가 보완하는 결손.**
- **Cold-start SFT**: 수천 개의 대화형·인간 친화적 사고 예시로 시작합니다. 자연스럽고 읽을 수 있는 사고 표현의 발판을 제공합니다.
- **Reasoning-oriented RL**: R1-Zero와 유사하게 추론 성능을 발전시키되, 대화형 사고 과정과 언어 일관성도 함께 다룹니다.
- **Rejection sampling + SFT**: RL 체크포인트에서 추론 데이터를 rejection sampling으로 만들고, 글쓰기·사실 QA·자기 인식 등 비추론 데이터를 결합해 다시 SFT합니다. 추론 성능 외에 일반 응답과 글쓰기 역량을 보완합니다.
- **두 번째 RL**: 다양한 시나리오의 프롬프트와 보상을 사용해 유용성·무해성을 맞추고 추론 능력도 추가로 다듬습니다.

즉, 두 차례 SFT가 초기 표현과 일반 역량을 보완하고, 두 차례 RL이 추론과 선호 정렬을 담당합니다. 논문은 이 과정을 두 SFT 단계와 두 RL 단계로 설명합니다.

**(c) 언어 일관성 보상과 그 비용.**
§3.2.1 식 (7)의 보상은 CoT에서 목표 언어 단어가 차지하는 비율입니다.

$$Reward_{\text{language}} = \frac{Num(Words_{\text{target}})}{Num(Words)}$$

이는 혼용을 줄여 가독성을 높이려는 보상입니다. 부록 B.6의 ablation에서는 동일한 cold-start 데이터를 쓴 DeepSeek-R1-Distill-Qwen-7B에서 LC 보상이 없을 때 학습이 진행될수록 언어 일관성이 악화됐고, LC 보상을 적용하면 그 일관성이 유지됐습니다. 반면 벤치마크에서는 수학 성능은 비슷하고 코딩 성능은 약간 저하됐습니다. 그러므로 이 보상은 가독성과 언어 일관성을 얻는 대신 특정 성능 지표에 비용을 낼 수 있다는 trade-off로 설명하는 것이 정확합니다. 이 결과는 해당 ablation 설정의 관측이지, 모든 모델·언어·과제에서 같은 비용이 생긴다는 뜻은 아닙니다.

### Q2. 보상 설계: 규칙 보상과 모델 기반 보상의 역할

**심사식 점검**
(i) **주장의 명료성**: 규칙 보상은 정답을 객관적으로 확인할 수 있는 추론 과제에, 모델 기반 보상은 복잡하고 미묘한 일반 선호를 평가하는 데 쓰였습니다. 논문은 모델 보상을 전면 배제한 것이 아닙니다.
(ii) **직접 근거**: §2.2의 식 (4)와 배제 이유 두 가지, §3.1의 V3 판정 과정, 부록 B.5의 보상 해킹 관측을 각각 구분합니다.
(iii) **경계 조건**: 부록 B.5는 helpful reward model을 이용한 특정 사례입니다. 모든 모델 기반 보상이 반드시 해킹된다는 뜻은 아니지만, 논문은 신뢰할 수 있는 보상 신호가 없는 과제에서 RL을 확장하는 것을 한계로 지적합니다.

**답안**

**(a) 식 (4)의 두 규칙 보상 항과 검증 방법.**

$$Reward_{\text{rule}} = Reward_{\text{acc}} + Reward_{\text{format}}$$

정확도 보상은 답의 정오를 검사합니다. 수학처럼 결정적 정답이 있는 문제에서는 모델이 최종 답을 `\boxed{}` 형식으로 내도록 해 ground truth와 비교할 수 있습니다. 코드 문제에서는 컴파일러와 사전 정의된 테스트 케이스로 실행 결과를 확인합니다.
형식 보상은 답변 구조를 검사합니다. 특히 사고 과정을 `<think>`와 `</think>` 태그 안에 두도록 보상합니다. 이는 정답 자체를 증명하는 항이 아니라, 추론 영역을 구분해 분석 가능하도록 하는 형식 제약입니다.

**(b) 추론 과제에서 신경망 보상 모델을 쓰지 않은 두 이유.**
§2.2는 outcome-based와 process-based 신경망 보상 모델을 추론 과제에 적용하지 않은 이유를 두 가지로 듭니다.
1. 대규모 RL 중 보상 모델의 편향이나 결함을 정책이 악용하는 **reward hacking** 위험이 있다고 관찰했습니다.
2. 보상 모델을 재학습하는 데 상당한 계산 자원이 들고, 학습 파이프라인과 최적화 과정이 더 복잡해집니다.

이는 추론에서 보상 모델을 전혀 쓰지 않는다는 뜻이 아니라, 검증 가능한 추론 보상은 규칙·정답 기반 신호를 우선한다는 선택입니다.

**(c) 일반 도메인에서 model-based reward가 필요한 이유와 위험.**
§3.1은 일반 데이터에서 helpfulness와 harmlessness를 평가할 때 사람 선호가 복잡하고 미묘하므로 보상 모델을 사용한다고 설명합니다. Helpful 평가에서는 DeepSeek-V3가 응답 쌍을 판정하도록 해 선호 데이터를 만들고, 응답 순서를 바꿔 여러 번 판정한 뒤 점수를 평균해 위치 편향을 줄입니다. Safety 평가는 전체 응답의 위험을 대상으로 별도의 안전 라벨·보상 모델을 사용합니다. 즉, V3 판정은 일반 helpfulness 선호 데이터를 구축하는 데 활용되고, 모든 일반 보상이 단순히 V3 단일 점수 하나인 것은 아닙니다.

위험은 보상 모델 점수와 실제 품질이 어긋날 수 있다는 것입니다. 부록 B.5는 helpful reward model을 사용한 학습에서 보상은 증가하는데 Codeforces 성능은 감소하는 현상을 reward hacking의 예로 듭니다. 모델이 인간 의도보다 보상 모델의 편향을 최적화할 수 있다는 경고입니다. 따라서 규칙 기반 검증이 어려운 개방형 글쓰기 등에서 model-based reward는 필요할 수 있지만, 신뢰도와 해킹 가능성 검증 없이 RL의 유일한 목표로 삼기는 어렵습니다.

### Q3. 증류 대 RL: 소형 모델에서 증류를 택한 이유

**심사식 점검**
(i) **주장의 명료성**: 저자들은 증류 학생에 RL을 추가하지 않은 이유를 "증류의 효과를 보이기 위해"라고 명시합니다. RL보다 증류가 보편적으로 우월하다고 주장한 것은 아닙니다.
(ii) **직접 근거**: 부록 F의 800k teacher-generated 샘플·SFT-only 선언과 Table 15의 성능을 구분해 인용합니다.
(iii) **경계 조건**: Table 15는 서로 다른 크기와 기반 모델의 결과를 보여주며, 증류와 RL을 동일 조건에서 직접 비교하는 통제 실험은 아닙니다. 논문도 RL을 더하면 성능이 상당히 향상될 수 있다고 명시합니다.

**답안**

**(a) 증류 모델에 SFT만 적용하고 RL을 추가하지 않은 이유.**
부록 F에 따르면 저자들은 DeepSeek-R1이 생성한 약 800,000개의 샘플로 Qwen·Llama 기반 모델을 SFT했습니다. 고품질 teacher 출력으로 학습한 모델이 인간 생성 데이터로 직접 학습한 모델보다 일관되게 좋은 결과를 보였다는 관찰을 배경으로, 학생 모델에는 SFT만 적용하고 RL 단계는 넣지 않았습니다. 저자들이 밝힌 목적은 RL까지 결합한 최종 성능을 최대화하는 것이 아니라 증류 자체의 효과를 보여주는 것입니다. 동시에 논문은 RL을 추가하면 성능이 크게 향상될 가능성을 인정하고, 그 탐구는 후속 연구에 남깁니다.

**(b) Table 15의 수치가 뒷받침하는 것.**
Table 15에서 DeepSeek-R1-Distill-Qwen-7B는 AIME 2024 pass@1 55.5, MATH-500 92.8을 기록합니다. Qwen-32B 기반 증류 모델은 각각 72.6, 94.3이고, Llama-70B 기반 모델은 70.0, 94.5입니다. 이 결과는 R1의 고품질 추론 출력이 더 작은 dense 모델에 강한 추론 능력을 전달할 수 있으며, 그 능력이 여러 벤치마크에서 높은 점수로 나타날 수 있다는 주장을 뒷받침합니다. 표에는 AIME cons@64도 제시되어 있는데, 해당 세 모델은 각각 83.3, 83.3, 86.7입니다.
하지만 이 표는 "증류가 RL보다 낫다"는 직접 증거가 아닙니다. 표의 모델들은 크기와 기반 아키텍처가 다르고, 증류 학생에 RL을 적용한 대조 결과도 포함되어 있지 않습니다.

**(c) "증류가 RL보다 낫다"는 주장에 필요한 범위 제한.**
그 주장을 하려면 반드시 **"이 논문에서 보고한 SFT-only 증류 설정과 선택한 모델·데이터·벤치마크 범위에서"**라고 한정해야 합니다. 논문은 증류 학생에 RL을 적용하지 않았다고 밝혔고, RL이 추가되면 성능이 더 오를 수 있다고 인정합니다. 그러므로 현재 수치는 증류가 소형 모델의 성능을 효율적으로 높이는 방법임을 지지할 뿐, 증류가 RL보다 일반적으로 우수함을 입증하지 않습니다.
논문의 한계 논의도 보상 신호를 신뢰성 있게 정의할 수 없는 개방형 과제에서는 RL이 reward hacking에 취약하고, 신뢰할 수 있는 평가·보상 신호가 연구 과제로 남아 있다고 지적합니다. 이는 증류와 RL 중 하나가 모든 과제에서 우월하다는 결론이 아니라, 데이터·모델 용량·보상 검증 가능성·학습 비용에 따라 선택이 달라진다는 범위 제한을 요구합니다.

## 🧩 핵심 메모 (정답 요약 — 답변 후 대조용)

- **RL의 한계와 4단계 파이프라인(§2.3 · §3).** RL 단독(R1-Zero)은 AIME 2024 pass@1을 15.6% → **77.9%**(cons@64 **86.7%**)까지 끌어올렸으나, 가독성 저하와 **언어 혼용**을 남겼습니다. 그 배경은 §3이 밝히듯 DeepSeek-V3-Base가 여러 언어(특히 영어·중국어)로 학습된 데 있습니다. R1은 이를 4단계로 보완합니다: ① 수천 건 cold-start SFT(대화형·인간 친화적 사고) → ② 추론 지향 RL(대화형 사고 + 언어 일관성) → ③ rejection sampling + SFT(추론 + 비추론: writing · factual QA · self-cognition · translation, 부록 B.3.2) → ④ 2차 RL(유용성·무해성 + 추론 재정련). 즉 **두 SFT가 표현·일반 역량**을, **두 RL이 추론·정렬**을 담당합니다.
- **보상 설계(§2.2 · §3.1).** 식 (4) `Reward_rule = Reward_acc + Reward_format` — 정확도 보상(수학 = box 형태 최종답, 코드 = **컴파일러**)과 형식 보상(`<think>` / `</think>` 태그)을 **동일 가중**으로 합합니다. **추론 과제에서는 신경망 RM(outcome·process)을 쓰지 않습니다**: (1) 대규모 RL에서 **보상 해킹**에 취약, (2) 재학습에 막대한 자원이 들고 파이프라인·최적화가 복잡해짐. 일반 도메인은 §3.1의 모델 기반 보상 — **helpful**(V3가 arena-hard 형식으로 쌍 판정, A/B 순서를 **4회** 교체 평균해 위치 편향 통제, Δ>1만 채택, 길이 편향 통제, **66,000 쌍**, 식 5, **최종 요약만** 평가)과 **safety**(**106,000** 프롬프트, safe/unsafe **point-wise** 라벨, 식 6, **전체 응답** 평가).
- **언어 일관성 보상의 비용(식 7 · 부록 B.6).** `Reward_language = Num(Words_target)/Num(Words)` — 미적용 시 학습이 진행될수록 언어 일관성이 악화되고, 적용 시 안정적으로 유지됩니다. 대가는 **수학 벤치마크 유사 · 코딩 벤치마크 소폭 저하**이며, 이는 Distill-Qwen-7B 단일 ablation의 관측입니다.
- **증류 대 RL(부록 F.1 · Table 16 · Table 15 · Table 6).** R1이 생성한 **800,000 샘플**로 Qwen·Llama 기반을 SFT(**RL 단계 없음**) — 목적은 "증류 기법의 효과 입증"이며, 저자들은 RL 추가 시 성능이 더 오를 수 있음을 인정합니다. 결과: Qwen-7B AIME **55.5** · MATH-500 **92.8**, Qwen-32B **72.6** · **94.3**, Llama-70B **70.0** · **94.5**(cons@64 83.3 / 83.3 / 86.7). **가장 강한 근거는 Table 16**: `Qwen2.5-32B-Base`라는 **동일 기반**에서 **RL만 10K+ 스텝**(`Qwen2.5-32B-Zero`)과 **증류만**(`R1-Distill-Qwen-32B`)을 비교하면 AIME pass@1 **47.0 → 72.6**, MATH-500 91.6 → 94.3, GPQA 55.0 → 62.1, LiveCodeBench 40.2 → 57.2로 **네 지표 전부 증류 우세**입니다. 다만 이는 **"강한 교사가 있을 때 소형 모델에서 증류가 더 효율적"** 이라는 조건부 결론이며(증류는 R1 출력 분포를 모방하므로 R1 부재 시 경로 자체가 불가), Table 15는 크기·기반이 다른 모델의 **비통제 비교**이므로 행 간 우열로 읽지 않습니다.
- **원문 내 불일치(§3.2.1).** "the **GRPO clip ratio ε to 10**"은 식 (1)의 clip 구간 `[1−ε, 1+ε]`와 모순됩니다 — `ε = 10`이면 하한이 `−9`라 **clip이 사실상 무력화**되고, 같은 절의 다음 문장("낮은 값은 그래디언트 절단 · 높은 값은 불안정")은 ε이 통상 범위임을 함의합니다. **원기(誤記) 의심**으로 기록하며, R1의 실효 ε은 원문만으로 결정할 수 없습니다. 함께 기록할 경계 조건: pass@1은 저장소 README 기준 **64회 생성**이고, arXiv 빌드(86쪽)와 저장소 동봉 PDF(1,328,991 B)는 **다른 빌드**입니다.
- **남은 한계(§6).** 순수 RL은 신뢰 가능한 보상 신호에 의존하므로, writing처럼 규칙으로 검증할 수 없는 과제에서는 **보상 해킹 위험**이 커져 확장이 미해결 과제로 남습니다. 그 밖에 구조화 출력·도구 사용 미비, 토큰 효율(과잉 추론), 언어 혼용, 프롬프트 민감성(few-shot가 성능을 일관되게 저하 → zero-shot 권장), 소프트웨어 엔지니어링의 RL 미적용이 한계로 제시됩니다.

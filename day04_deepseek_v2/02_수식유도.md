# 02. 수식 유도 — MLA(저랭크 KV 압축 + decoupled RoPE)와 DeepSeekMoE

> DeepSeek-V2(2405.04434)의 두 핵심을 식 단위로 분해한다.
> 관통 목표: **"KV cache 병목을 *표현력 손실 없이* 없애는 저랭크 압축 + 흡수"**.

| 기호 | 의미 |

## PART A. MLA

### A.1 KV cache 문제

MHA에서 토큰 1개의 KV cache:

```
KV_MHA = 2 · n_h · d_h · l        (K 와 V, 각 헤드×차원, 모든 레이어)
```

V2 설정으로 계산하면 `2·128·128·60 = 1,966,080` 요소/토큰. 128K 문맥이면 fp16에서 **~480 GB** → 병목.

### A.2 저랭크 KV 결합 압축 (식 9–11)

```
c_t^KV = W^DKV h_t            ,  W^DKV ∈ R^{d_c × d}          ... (9)   다운프로젝션
k_t^C  = W^UK  c_t^KV         ,  W^UK  ∈ R^{n_h d_h × d_c}    ... (10)  업프로젝션(key)
v_t^C  = W^UV  c_t^KV         ,  W^UV  ∈ R^{n_h d_h × d_c}    ... (11)  업프로젝션(value)
```

**추론 시 cache 에는 `c_t^KV` 하나만** 저장:

```
KV_MLA(KV만) = d_c · l                  (d_c ≪ n_h d_h)
```

> 직관: K와 V는 **서로 강하게 상관**하므로 **공통 저랭크 공간**으로 한 번에 압축해도 정보 손실이 작다. (GQA는 헤드를 묶어 손실이 크다.)

### A.3 Query 저랭크 압축 (식 12–13)

```
c_t^Q = W^DQ h_t  ,  q_t^C = W^UQ c_t^Q        ... (12)(13)
```

- KV cache는 못 줄이지만 **학습 시 활성 메모리(activation) 절감**. (성능엔 이득)

### A.4 흡수(absorption) 항등식

`q^C = W^UQ c^Q`, `k^C = W^UK c^KV` 이므로 (헤드 i에 대해, 행 블록 `W^UQ_i, W^UK_i`):

```
(q_t^C)ᵀ (k_s^C)  =  (W^UQ_i c_t^Q)ᵀ (W^UK_i c_s^KV)
                  =  (c_t^Q)ᵀ ( W^UQ_iᵀ W^UK_i ) c_s^KV
                  =  (c_t^Q)ᵀ A_i c_s^KV ,      A_i := W^UQ_iᵀ W^UK_i     ... (★)
```

- 즉 **`A_i` 를 미리 접으면 K·V를 만들 필요가 없다**. (`W^UV`는 출력에서 `W^O`로 흡수)
- §03 실습에서 `max|직접 − 흡수| ≈ 1e-11` 로 수치 검증.

### A.5 decoupled RoPE (식 12–19)

RoPE는 위치민감 → `k^C`에 걸면 `W^UK`가 위치행렬과 **얽혀** (★) 성립 불가(행렬곱 비가환):

```
RoPE(k_s^C) = R_s · W^UK c_s^KV   ⇒   (c_t^Q)ᵀ A_i R_s c_s^KV  (R_s 가 가운데 끼어 못 접음)
```

해법: RoPE를 **별도 소채널**에만:

```
q_t^R = RoPE(W^QR c_t^Q)       ... (14)   (n_h·d_h^R)
k_t^R = RoPE(W^KR h_t)         ... (15)   (d_h^R, 헤드 공유)
q_{t,i} = [q_{t,i}^C ; q_{t,i}^R]   ... (16)
k_{t,i} = [k_{t,i}^C ; k_t^R]       ... (17)
o_{t,i} = Σ_j Softmax_j( q_{t,i}ᵀ k_{j,i} / √(d_h + d_h^R) ) v_{j,i}^C   ... (18)
u_t = W^O [o_{t,1}; … ; o_{t,n_h}]   ... (19)
```

스코어 분해:

```
q_tᵀ k_s = (q_t^C)ᵀ k_s^C  +  (q_t^R)ᵀ k_s^R
           └─ 흡수 가능(★) ─┘   └─ 소채널 명시 계산 ─┘
```

**총 KV cache:**

```
KV_MLA = (d_c + d_h^R) · l = (512 + 64) · 60 = 34,560 요소/토큰
```

V2 설정 MHA 대비 `1 − 34560/1966080 = 98.24%` 감소. (논문 headline은 DeepSeek 67B 대비 **−93.3%**.)

## PART B. DeepSeekMoE

### B.1 출력 (식 20)

```
h_t' = u_t + Σ_{i=1}^{N_s} FFN_i^(s)(u_t)  +  Σ_{i=1}^{N_r} g_{i,t} FFN_i^(r)(u_t)   ... (20)
```

- `N_s` 공유 전문가(항상 활성) + `N_r` 라우팅 전문가(top-K 선택).

### B.2 게이트 (식 21–22)

```
s_{i,t} = Softmax_i( u_tᵀ e_i )                                              ... (22)
g_{i,t} = s_{i,t}   if  s_{i,t} ∈ Topk({s_{j,t}}, K_r)   else 0              ... (21)
```

### B.3 왜 "잘게 + 공유"인가

- **Fine-grained**: 총 전문가를 `m`배로 쪼개고 활성도 `m`배 → **조합 수** `C(N,K)` 급증 → 표현력↑ (같은 활성 파라미터).
- **Shared expert**: 공통 지식을 **전담** → 라우팅 전문가들이 공통 지식을 **중복 학습**하지 않음 → 전문화 촉진·중복 제거.

V2: `N_s=2`, `N_r=160`, `K_r=6`, expert hidden 1536 → **236B 총 / 21B 활성**.

### B.4 부하 균형 (V2 방식)

- 토큰을 전문가에 고르게 분배(편중 시 일부 전문가만 학습) → **보조 손실/디바이스 제한 라우팅**으로 제어.
- (V3: **auxiliary-loss-free** balancing + MTP + FP8 → Day 05)

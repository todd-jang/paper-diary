## 0. 전체 구조

```
[Block]  ── MLA (어텐션, V2와 동일 계열 + YaRN 파라미터)  ──  MoE (FFN)
                                                              ├─ Gate        ← 여기서 aux-loss-free
                                                              ├─ 256 routed Expert (EP로 분산)
                                                              └─ 1 shared Expert(=MLP)
앞 3개 층(n_dense_layers=3)은 Dense MLP  ← config 그대로
```

- `Block = MLA + MoE`, `Transformer = 61 × Block + RMSNorm + head`.
- **학습 전용인 MTP 모듈은 추론 코드에 존재하지 않는다** — `mtp`/`MTP`/`extra_token` 검색 결과 **0건**. 논문 §2.2 "추론 시 MTP 모듈은 버린다"와 정확히 일치한다(아래 PART D).

## PART A. `Gate` — aux-loss-free는 bias 한 줄에서 시작한다

### A.0 편향 파라미터의 선언 (model.py:563–564)

```python
self.weight = nn.Parameter(torch.empty(args.n_routed_experts, args.dim))
self.bias = nn.Parameter(torch.empty(args.n_routed_experts, dtype=torch.float32)) if self.dim == 7168 else None
```

- **`self.dim == 7168`일 때만** 편향이 생성된다. 7168은 V3-671B의 hidden 차원 → 즉 편향은 **"V3 671B 전용 스위치"** 로 하드와이어되어 있다.
- `requires_grad`가 아니라 **버퍼에 가까운 학습 대상이 아닌 파라미터**로, 옵티마이저가 아니라 **규칙(bias update)** 으로 갱신된다(논문 §2.1.2의 `γ`). *(초기값 로딩은 체크포인트에서 온다.)*

### A.1 forward 5단계 (model.py:566–598)

```python
scores = linear(x, self.weight)
if self.score_func == "softmax": scores = scores.softmax(dim=-1, dtype=torch.float32)
else:                            scores = scores.sigmoid()
original_scores = scores
if self.bias is not None:        scores = scores + self.bias
```

1. **점수 계산** → `score_func = "sigmoid"` (V3는 V2의 softmax에서 **시그모이드**로 변경)
2. **`original_scores` 보존** ← 이 한 줄이 "점수 왜곡 0"의 근거다
3. **선택용 점수에만 bias를 더함** (식 16)

```python
if self.n_groups > 1:
    scores = scores.view(x.size(0), self.n_groups, -1)
    if self.bias is None: group_scores = scores.amax(dim=-1)
    else:                 group_scores = scores.topk(2, dim=-1)[0].sum(dim=-1)
    indices = group_scores.topk(self.topk_groups, dim=-1)[1]
    mask = scores.new_ones(x.size(0), self.n_groups, dtype=bool).scatter_(1, indices, False)
    scores = scores.masked_fill_(mask.unsqueeze(-1), float("-inf")).flatten(1)
indices = torch.topk(scores, self.topk, dim=-1)[1]
weights = original_scores.gather(1, indices)
if self.score_func == "sigmoid": weights /= weights.sum(dim=-1, keepdim=True)
weights *= self.route_scale
```

4. **노드 제한 라우팅** — `n_groups=8`(노드 8개), `topk_groups=4`(노드 최대 4개) → **`M=4`**. 선택되지 않은 그룹은 `-inf`로 마스킹되어 후보에서 제거된다.
   - 그룹 점수는 bias가 있으면 **`topk(2).sum`** — 논문 §2.1.2의 *"각 노드에서 상위 `K_r/M` 점수의 합으로 노드를 고른다"* 의 구현이다(`K_r=8, M=4` → 2개 합).
5. **가중치는 `original_scores`에서 gather** → bias는 **선택에만** 관여하고 가중치엔 **전혀** 들어가지 않는다. 그 다음 시그모이드 정규화(합=1) 후 `route_scale=2.5` 곱.

> **핵심:** "선택"과 "가중치"가 코드에서 **다른 텐서**(`scores` vs `original_scores`)로 분리되어 있다. 이것이 aux-loss-free가 **점수를 왜곡하지 않는다**는 구조적 보장이다.

### A.2 `bias`는 누가 갱신하나?

- 추론 코드에는 bias 갱신 루프가 **없다**(학습 프레임워크의 몫). 논문 §2.1.2: 매 스텝 **배치 부하를 보고** 과부하 전문가는 `−γ`, 부족 전문가는 `+γ`.
- 실습 [SIM]에서 재현한 결과(§03): 잔여 불균형이 `γ`에 **단조 증가**하고 스텝 수를 늘려도 값이 같다 → **`b_i ← b_i + γ·sign(e_i)`는 고정스텝 적분기 = 진폭 ∝ γ인 극한순환**. 논문이 `γ=0.001`(14.3T)로 **작게** 잡고 마지막 500B에서 **0.0으로 끄는** 이유의 코드-수준 대응이다.

## PART B. `MoE` — 토큰을 전문가별로 모아 계산

### B.1 초기화 (model.py:656–667)

```python
self.n_local_experts = args.n_routed_experts // world_size
self.experts_start_idx = rank * self.n_local_experts
self.gate = Gate(args)
self.experts = nn.ModuleList([Expert(args.dim, args.moe_inter_dim) if self.experts_start_idx <= i < self.experts_end_idx else None
                              for i in range(args.n_routed_experts)])
self.shared_experts = MLP(args.dim, args.n_shared_experts * args.moe_inter_dim)
```

- **`256 // world_size`** — 전문가를 EP 랭크에 나눠 담고, 자기 담당 범위 밖은 `None`(메모리에 없음).
- **공유 전문가 = `n_shared_experts × moe_inter_dim`** 크기의 **하나의 MLP**(`N_s=1`). "1개"를 별도 `ModuleList`로 두지 않고 **넓은 MLP 한 덩어리**로 표현한 것이 재미있다 — gating 없이 항상 통과하므로 굳이 분리할 필요가 없다.

### B.2 forward (model.py:679–693)

```python
x = x.view(-1, self.dim)
weights, indices = self.gate(x)
y = torch.zeros_like(x)
counts = torch.bincount(indices.flatten(), minlength=self.n_routed_experts).tolist()
for i in range(self.experts_start_idx, self.experts_end_idx):
    if counts[i] == 0: continue
    expert = self.experts[i]
    idx, top = torch.where(indices == i)
    y[idx] += expert(x[idx]) * weights[idx, top, None]
z = self.shared_experts(x)
if world_size > 1: dist.all_reduce(y)
return (y + z).view(shape)
```

- **`counts == 0`이면 skip** → 놀고 있는 전문가의 연산을 아예 건너뛴다.
- `weights[idx, top, None]` — 토큰이 전문가 `i`를 **몇 번째로 골랐는지**(`top`)에 해당하는 가중치를 정확히 집어 곱한다.
- `shared_experts(x)`는 **라우팅 없이 전 토큰**에 적용 → `(y + z)`.
- `Expert = w2(silu(w1(x)) * w3(x))` (SwiGLU).

> **"토큰 드롭이 없다"** 는 논문 주장(§2.1.2)이 코드에서도 성립한다: 어떤 경로에도 토큰을 **버리는 분기**가 없다(용량 한계·드롭 마스크 없음). 부하 균형을 맞추는 책임은 전적으로 `Gate`의 bias와 학습 스케줄에 있다.

## PART C. FP8 `Linear` — 블록 스케일은 파라미터로 등록된다

### C.1 `Linear.__init__` (model.py:179–189)

```python
self.weight = nn.Parameter(torch.empty(out_features, in_features, dtype=dtype or Linear.dtype))
if self.weight.element_size() == 1:
    scale_out_features = (out_features + block_size - 1) // block_size
    scale_in_features  = (in_features  + block_size - 1) // block_size
    self.weight.scale = self.scale = nn.Parameter(torch.empty(scale_out_features, scale_in_features, dtype=torch.float32))
else:
    self.register_parameter("scale", None)
```

- `element_size() == 1` = **FP8 가중치**일 때만 스케일을 만든다. shape이 **`ceil(out/128) × ceil(in/128)`** → **가중치 128×128 블록 스케일**(논문 §3.3.2의 "per 128 input channels × 128 output channels")이 그대로 드러난다.
- 스케일은 `float32` 파라미터다(양자화 계수를 학습/전달 대상으로 관리).

### C.2 `linear()` 디스패치 (model.py:131–160)

```python
if weight.element_size() > 1:
    return F.linear(x, weight, bias)
...
weight = weight_dequant(weight, weight.scale)
x, scale = act_quant(x, block_size, scale_fmt)
y = fp8_gemm(x, scale, weight, weight.scale)
```

- bf16 가중치면 그냥 `F.linear` → **같은 코드가 bf16/fp8 두 모드로 돈다**(`gemm_impl`, `dtype`은 `ModelArgs`에서 온다).
- FP8 경로: **가중치 역양자화 → 활성 양자화 → `fp8_gemm`**.

### C.3 `kernel.py` — 스케일은 448로 나누고, 필요하면 2의 거듭제곱으로 반올림

```python
amax = tl.max(tl.abs(x))
amax = tl.maximum(amax, 1e-4)
s = amax / 448.
if scale_fmt == "ue8m0": exp = tl.math.ceil(tl.math.log2(s))   # 2의 거듭제곱 스케일
```

- **`448.`** = E4M3가 표현할 수 있는 최대 절대값 → `s = amax/448`이 표준 스케일.
- `amax`를 `1e-4`로 **클램프**(0으로 나누기 방지).
- `scale_fmt="ue8m0"`이면 `ceil(log2 s)` → **`2^k` 격자 스케일**. 논문 §3.3.3의 *"scaling factors are round scaled, i.e. integral power of 2"*(attention 뒤 Linear 입력, MoE up-projection 입력)의 구현이다.
- `act_quant` 출력 dtype = **`torch.float8_e4m3fn`**, 마지막 차원이 128로 나누어떨어져야 함(`block_size=128`). 스케일 shape = `(*x.shape[:-1], x.shape[-1]//128)` → **활성 1×128 타일**.
- `weight_dequant(weight, scale)`의 스케일 shape은 **`(M//128, N//128)`** 로 문서화되어 있어 가중치 블록 양자화가 재확인된다.

### C.4 `ModelArgs`에 드러난 FP8 손잡이 (model.py:28, 57–58)

| 필드 | 의미 |
|---|---|
| `dtype: Literal["bf16", "fp8"]` | GEMM 정밀도 모드 |
| `scale_fmt: Optional[str]` | 스케일 형식(예: `ue8m0` = 2의 거듭제곱) |
| `beta_fast: 32`, `beta_slow: 1`, `mscale` | YaRN 문맥확장 파라미터(논문 §4.3의 `β=32`, `α=1`에 대응) |
| `max_seq_len: 4096*4` | 기본 16K(=1단계 확장값과 같은 자리) |

> 논문의 "FP32 승격(promotion)"은 Triton 커널(`fp8_gemm_kernel`) 내부 누산 전략으로 들어가 있어 파이썬 레벨에서는 보이지 않는다 — 코드만 읽으면 **놓치는 부분**(§3.3.2의 `N_C=128`).

## PART D. MTP는 추론 코드에 없다 (의도된 부재)

- `model.py` / `generate.py`에서 `mtp`, `MTP`, `extra_token`, `logits_list` **전부 0건**.
- 논문 §2.2: *"our MTP strategy mainly aims to improve the performance of the main model, so during inference, we can directly discard the MTP modules"* → **추론 경로가 아예 본체만 남긴다**.
- `Transformer.forward`는 단일 `logits`를 반환하고 `generate.py`는 순수하게 다음 토큰을 이어붙인다. 즉 MTP는 **학습 시에만 존재하는 보조 목표**이고, 추론 가속(speculative decoding)으로 쓰려면 MTP 모듈을 **별도로 붙여야** 한다.
- 실습에서 검증한 것은 이 학습-경로의 성질이다: 창(창 안 t+1) 안쪽 임베딩에만 의존(3.76e+00), 창 밖은 **정확히 0**, 공유 임베딩·헤드로 **그래디언트가 흐른다**(embed 2.43e-01 / head 5.73e+00 / proj 1.02e+01).

## 한눈에 보는 요약

| 부품 | V2 | V3 (코드에서 확인) | 이득 |
|---|---|---|---|
| `Gate` 점수 | softmax | **sigmoid** + `original_scores` 보존 | 가중치 왜곡 0 |
| 부하 균형 | aux loss | **`bias`(선택 전용)** + `γ` 스케줄(0.001 → 0.0) | 균형을 성능 손해 없이 |
| 노드 제한 | device-limited | **`n_groups=8 · topk_groups=4`** (`M=4`) | 통신비 ↓ |
| 드롭 | 토큰 드롭 | **드롭 분기 없음** | 토큰 손실 0 |
| FFN 정밀도 | BF16 | **FP8 + 128×128 / 1×128 스케일 + `ue8m0` 옵션** | 속도 ×2 이론치·메모리 ↓ |
| MTP | 없음 | **학습 전용(추론 코드에 부재)** | 벤치 ↑ |

**핵심 문장:** V3의 세 기법은 코드에서 **한 줄씩** 대응된다 — *"선택에는 `+bias`, 가중치에는 원점수"*(aux-loss-free), *"128×128 스케일 파라미터"*(FP8), *"추론 코드에 없는 MTP"*(학습 전용 목표). 즉 **"무엇을 건드리지 않는가"** 가 V3 설계의 본질이다.

## 2. 결과 읽기

### (1) GRPO — 가치망 없이도 세 가지가 성립하고, 하나가 부산물로 나온다

| 성질 | 실측 | 판정 |
|---|---|---|
| `Σ_i A_i = 0` [EXACT] | `0.00e+00` | **항등식 성립** (부동소수 오차조차 0) |
| 스케일 불변 [EXACT] | 정규화 시 `4.66e-10` / 미정규화 시 `100.0배` | **성립** — 잔차는 부동소수 누적 오차 |
| 평행이동 불변 [EXACT] | 정규화 시 `0.00e+00` / 미정규화 시 상대변화 `6.220` | **성립** |
| 난이도 게이팅 [SIM] | 전원정답/전원오답 그룹 비율 `0.312 → 0.969` | **학습이 진행될수록 학습 신호가 소멸** |

- **해석.** 정답 확률이 `easy 0.903 / mid 0.522 / hard 0.106`에서 각각 `0.997 / 0.995 / 0.993`으로 올라갔습니다. 세 버킷 모두 **포화**하며, 그 결과 그룹 내 분산이 0인 그룹(전원 정답)의 비율이 `31.2% → 96.9%`로 증가합니다. 즉 **GRPO는 스스로 학습 신호를 소진**합니다 — 이것은 버그가 아니라 식 (3)의 구조적 귀결이며, 실전에서는 이 시점에 **더 어려운 질문을 공급**해야 한다는 §2.1의 설계(난이도 분포 관리)와 연결됩니다.
- **미정규화 비교가 이 검증의 의미를 만듭니다.** 같은 롤아웃·같은 보상에 스케일만 100배 했을 때, 그룹 정규화가 있으면 그래디언트가 **변하지 않고**(`4.66e-10`), 없으면 정확히 **100배**가 됩니다. 평행이동에서도 정규화는 `0.00e+00`인데 미정규화는 **보상 기준점을 옮기는 것만으로 갱신이 6.22배 바뀝니다**. 보상 함수의 절대 스케일·기준점을 설계하지 않아도 되는 이유가 이 두 수치입니다.
- **경계 조건.** 이 검증은 **문맥 밴딧 축소 설정**(질문 64개 · 행동 4개 · 그룹 8개 · 200스텝)의 정책경사입니다. 식 (1)의 clip·KL은 구현 범위 밖입니다(`01_코드워크스루.md` PART C 도입부).

### (2) 규칙 보상 — 두 항은 다른 실패 모드를 잡고, 형식은 검증의 입력 조건이다

- **`정답·형식 무 = 0.0`이 형식의 필요성을 보여줍니다.** 정답을 맞혔지만 box가 없으면 파서가 값을 꺼내지 못해 **정확도 보상이 0**입니다(`accuracy_lost_without_box = True`). 즉 `Reward_format`은 가독성 장식이 아니라 **`Reward_acc`의 전제조건**입니다.
- **두 항은 서로를 대체하지 않습니다.** `오답·형식 유 = 1.0`은 정확도 항이 없으면 잘못된 답이 보상된다는 뜻이고, `정답·형식 무 = 0.0`은 형식 항이 없으면 맞힌 답이 보상되지 않는다는 뜻입니다. **같은 가중(same weight)** 으로 더하는 식 (4)가 두 실패 모드를 함께 덮는 이유입니다.
- **해킹 표면의 크기: `0.50`.** 정답을 하나도 못 맞히고 형식만 갖춘 정책의 평균 형식 보상이 `0.50`입니다(정답률 0인데 보상 0이 아님). 여기서 README의 "생각 우회" 경고가 실제로 값을 갖습니다 — `오답·우회형식`은 `0.5`로 **강등**되어 `오답·형식 유`(1.0)의 절반입니다. 다만 **완전 봉쇄는 아닙니다**: 구조만 온전한 오답은 여전히 `0.5`를 받습니다.
- **경계 조건.** 두 항이 동일 가중이라는 사실은 §2.2 원문이 명시합니다("combined with the same weight"). 계산이 곧 정의이므로 [EXACT]입니다 — 여기서 "측정"한 것은 파서의 **동작**이지 성능이 아닙니다.

### (3) 언어 일관성 보상 — 혼용률은 급격히, 과제 성능은 완만하게

**(a) λ 스윕 [SIM].** λ = 0 → 혼용률 `93.9%` · 과제 성공률 `100.0%`. λ > 0 → 혼용률 **0.0–2.1%** 로 붕괴하고 과제 성공률은 **91.7%** 로 내려앉습니다. 즉 **λ는 거의 스위치처럼 작동**합니다(λ = 0.02에서 이미 혼용률 0.1%). λ = 0.05의 `2.1%`는 λ = 0.02·0.10보다 오히려 높은데, 이는 600스텝에서 코너로 완전히 수렴하지 못한 **잔차**이며 5개 시드 평균으로도 남았습니다 — 코너 해에서는 중간값이 안정점이 아니기 때문입니다.

**(b) 비용 곡선 [EXACT + 표본].** 위 스윕은 "정책이 어느 코너로 가는가"만 보여주므로, **λ를 우회해 목표어 비율 `q`를 직접 스윕**했습니다.

| 목표어 비율 `q` | 혼용률 `1−q` | 과제 성공률(해석해) | 과제 성공률(표본) |
|---|---|---|---|
| 0.00 | 100.0% | **100.0%** | 100.0% |
| 0.25 | 75.0% | 99.8% | 99.8% |
| 0.50 | 50.0% | 98.8% | 98.8% |
| 0.75 | 25.0% | 96.2% | 96.5% |
| 1.00 | 0.0% | **91.6%** | 91.5% |

- 해석해와 표본이 **0.3%p 이내로 일치**하므로, 표본 수(20,000)가 충분하고 모델이 해석식과 같은 것을 재고 있음이 확인됩니다.
- **읽는 법.** 혼용률을 100% → 0%로 없애는 비용은 과제 성공률 **100.0% → 91.6%, 즉 8.4%p** 입니다. 그리고 이 비용은 **혼용률이 줄어드는 만큼 완만하게** 지불됩니다(75% 제거 시 0.2%p만 지불, 마지막 25% 제거에 4.6%p). 원문 B.6의 "수학 유사 · 코딩 소폭 저하"와 **모양이 일치**합니다.
- **경계 조건 3건.** ① 이 곡선은 **가정**(외국어 추론 슬롯의 진행 확률 1.0 / 목표어 0.7)에서 유도되며, 논문은 그 미시 기구를 주지 않습니다 — 우리가 명시한 가정입니다. ② 토큰 예산 고정(`S = 4`)과 "과제 성공 = 진행 슬롯 2개 이상"이 성립해야 합니다. ③ B.6은 **Distill-Qwen-7B 단일 설정**의 관측이며, 곡선의 **형태**가 같다는 것이지 **수치가 같다는 것이 아닙니다**.

### (4) 보상 해킹 — 게이트 없이는 프록시와 진실이 갈라진다

| | 프록시 보상 | 실제 정답률 |
|---|---|---|
| **게이트 없음** | `0.412 → `**`1.000`** (↑) | `0.125 → `**`0.000`** (↓) |
| **검증 게이트** | `0.412 → 0.300` (↓) | `0.125 → `**`1.000`** (↑) |

- **게이트 없음**에서 정책은 **길이 부풀리기**로 전부 이동합니다: 프록시는 **최대(1.000)** 에 도달하는데 실제 정답률은 **0(정확히 0.000)** 입니다. 부록 B.5가 Figure 6으로 보고한 모양(보상↑ · Codeforces↓)이 그대로 재현됩니다.
- **게이트 있음**에서는 보상이 `노력`에만 인정되므로 최적 행동이 바뀝니다: 프록시는 **내려가고**(1.000 → 0.300 — 보상이 줄어드는 것이 정상입니다) 실제 정답률은 **1.000** 이 됩니다. **해소의 원리는 "보상을 줄여서"가 아니라 "프록시의 최적점을 진실과 일치시켜서"** 입니다.
- **경계 조건.** 프록시에 **체계적 편향**이 있어야 합니다(여기서는 길이 부풀리기 1.0 > 노력 0.3). 편향이 없는 보상 모델에는 해킹이 생기지 않으며, 원문도 "if the reward model contains systematic biases or inaccuracies"라고 조건을 명시합니다. 또한 게이트는 **검증 가능한 과제**에만 존재합니다 — §6이 "신뢰할 수 있는 보상 신호"를 미해결 과제로 남기는 이유입니다.

## 4. 실패/삽질 기록

1. **스케일 불변 검증이 거짓 실패했다 (검증 하네스 버그).** 첫 실행에서 정규화 시 스케일 불변 잔차가 `7.73e-01`로 "실패"했습니다. 원인은 GRPO가 아니라 **검사 코드**였습니다 — 분자를 `100·r`로 바꾸면서 분모 `std`는 **스케일 전 보상**에서 계산한 값을 그대로 썼습니다(분모가 1/100로 작동). 스케일된 `r`에서 표준편차를 다시 계산하니 `4.66e-10`으로 0이 되었습니다. **→ "검증 실패"를 보면 검증 코드부터 의심할 것.** 수정 라인: `r1_demo.py` 101–113.
2. **분산 감소를 잘못 측정했다(주장 자체를 교체).** "그룹 베이스라인이 분산을 줄인다"를 **질문 간 분산**으로 재려 했으나, 중심화 점수와 원점수는 **스케일이 달라** 비율이 무의미했습니다(0.61배로 나온 값은 축소가 아니라 스케일 차이). 더 이상한 것은 이 방향(베이스라인 추가 시 분산 증가)이 이론과 반대라는 점입니다. **→ 측정 불가능한 주장은 지우고, 대신 [EXACT]인 평행이동 불변으로 교체**했습니다(`0.00e+00` vs 미정규화 `6.220`). 남는 교훈: **모호한 지표는 정확한 항등식으로 대체하는 편이 낫다.**
3. **보상 해킹이 재현되지 않았다(모델 구조 문제).** 첫 설계는 `e`(노력)와 `ℓ`(길이)를 **독립 베르누이**로 두고 `proxy = 1.0·ℓ + 0.3·e`로 했습니다. 결과는 프록시 `0.938 → 1.263`에 실제 정답률 `0.625 → 0.875` — **둘 다 상승**해 해킹이 아닙니다. 두 손잡이가 **경쟁하지 않기** 때문입니다. **고정 예산 아래 세 행동 중 하나를 고르는 범주형 정책**(노력 0.3 / 부풀리기 1.0 / 포기 0.0)으로 바꾸자 프록시 `0.412 → 1.000`, 실제 `0.125 → 0.000`으로 **의도한 모양**이 나왔습니다. **→ 해킹을 재현하려면 "프록시가 선호하는 행동"과 "실제로 좋은 행동"이 같은 자원을 두고 경쟁해야 한다.**
4. **`detach()`가 옵티마이저 그래프를 끊었다.** `reward_hacking`에서 확률 `p_e = sigmoid(θ_e).detach()`로 두고 그 `p_e`로 로그확률을 계산해 `backward()`가 `RuntimeError: element 0 of tensors does not require grad`로 죽었습니다. 표본 추출에만 `.detach().cpu()`를 쓰고 로그확률은 **그래프가 붙은 `p`** 로 계산하도록 수정했습니다. **→ Day 5 실습 기록 3번과 같은 부류의 오류**(학습 경로에서 detach).
5. **원문 인용 판정을 PDF 추출 아티팩트가 왜곡했다(중요).** §2.2의 정확도 보상 문장은 "a compiler can be utilized to evaluate the model's performance, **responses against a suite of predefined test cases**, thereby generating objective feedback on correctness"인데, **Figure 1(전폭 삽입 그림)이 문단을 가로질러** 텍스트 추출에서 문장 중간이 잘려 나갔습니다. 이 때문에 "사전 정의된 테스트 케이스"가 **원문에 없는 보강**이라고 잘못 판정했습니다. PDF의 페이지 번호(`3`)와 그림 블록 순서를 대조해 **문장 연속**임을 확인했고, 채점 기록을 정정했습니다(`Day06_DeepSeekR1.md` 채점 & 교정). **→ 전폭 그림이 끼어든 문단은 문장이 분리되어 추출된다. 인용 판정 전에 페이지 흐름을 확인할 것.**
6. **표 번호를 잘못 기록했다.** 단계별(R1-Zero → Dev1 → Dev2 → Dev3 → R1) 수치를 "Table 8"로 적었으나, 원문에서 이 표는 **Table 3**이고 **Table 8**은 R1과 대표 모델 비교표입니다. 표 캡션 전수(`grep "^Table [0-9]*|"`)로 확인해 정정했습니다.
7. **파일 전면 재작성이 실패했다.** 편집 도구가 아니라 `write`로 전체를 덮어쓰려 하자 "File already exists"로 거부되어, **직전 편집분만 디스크에 남고 나머지 수정이 적용되지 않은 상태**로 한 번 실행했습니다(그 실행의 MPG 오류와 무효 수치가 여기서 나왔습니다). 이후 `edit`으로만 수정했습니다.

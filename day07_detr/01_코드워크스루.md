## 2. 식 (1) 매칭 비용 — `models/matcher.py`

논문 식 (1): $\hat\sigma=\arg\min_{\sigma\in\mathfrak S_N}\sum_i \mathcal L_{\text{match}}(y_i,\hat y_{\sigma(i)})$

```python
# models/matcher.py:65-77
# Compute the classification cost. Contrary to the loss, we don't use the NLL,
# but approximate it in 1 - proba[target class].
# The 1 is a constant that doesn't change the matching, it can be ommitted.
cost_class = -out_prob[:, tgt_ids]

# Compute the L1 cost between boxes
cost_bbox = torch.cdist(out_bbox, tgt_bbox, p=1)

# Compute the giou cost betwen boxes
cost_giou = -generalized_box_iou(box_cxcywh_to_xyxy(out_bbox), box_cxcywh_to_xyxy(tgt_bbox))

# Final cost matrix
C = self.cost_bbox * cost_bbox + self.cost_class * cost_class + self.cost_giou * cost_giou
```

- **핵심 대조:** 코드의 주석이 논문 문장을 그대로 옮겨 적었다 — *"Contrary to the loss, we don't use the NLL, but approximate it in 1 − proba[target class]"*. 즉 `cost_class = −p̂`(확률)이고, 손실 쪽은 `−log p̂`(로그 우도)다. 실습 [A]가 재현한 "확률 vs 로그" 분기점이 **코드 주석과 1:1로 대응**한다.
- `out_prob = outputs["pred_logits"].flatten(0, 1).softmax(-1)` (58행) — 매칭 전에 softmax로 확률화.

```python
# models/matcher.py:78-82
C = C.view(bs, num_queries, -1).cpu()
sizes = [len(v["boxes"]) for v in targets]
indices = [linear_sum_assignment(c[i]) for i, c in enumerate(C.split(sizes, -1))]
```

- **헝가리아리안 = `scipy.optimize.linear_sum_assignment`** (import는 6행). 배치별로 GT 수만큼 잘라서 각각 풀고, `(i, j)` 인덱스 쌍을 돌려준다.
- 가중치(1, 5, 2)는 `main.py` 인자로 들어온다:

```python
# main.py:67-71
parser.add_argument('--set_cost_class', default=1, type=float, ...)
parser.add_argument('--set_cost_bbox', default=5, type=float, ...)
parser.add_argument('--set_cost_giou', default=2, type=float, ...)
```

- matcher docstring(13-18행)이 **one-to-one 매칭의 의미를 명시**: *"we do a 1-to-1 matching of the best predictions, while the others are un-matched (and thus treated as non-objects)"* — 논문 §3.1의 "each target element has a unique match"와 같은 문장이다.

```python
# hybrid_encoder.py:192-193  (use_encoder_idx=[2] = 마지막 스케일 하나만 = S5)
use_encoder_idx=[2],
num_encoder_layers=1,
```

```python
# hybrid_encoder.py:288-303  (투영 → S5만 flatten → self-attention → 되돌림)
proj_feats = [self.input_proj[i](feat) for i, feat in enumerate(feats)]
for i, enc_ind in enumerate(self.use_encoder_idx):
    h, w = proj_feats[enc_ind].shape[2:]
    src_flatten = proj_feats[enc_ind].flatten(2).permute(0, 2, 1)   # Q=K=V=Flatten(S5)
```

- 이 3~4줄이 **논문 식 (1)의 `Q=K=V=Flatten(S5)` / `F5=Reshape(AIFI(...))` 그 자체**다. `use_encoder_idx=[2]`가 "인코더는 S5에만"이라는 D_S5 설정을 코드에서 강제한다.
- `input_proj`(212-219행): 각 스케일의 채널을 1×1 conv + BN으로 256에 맞추는 **채널 투영**(논문 식에는 생략된 부분).

```python
# hybrid_encoder.py:306-323  (cross-scale 융합 = CCFF)
# top-down (FPN 방향)
feat_high = self.lateral_convs[...](feat_high)
upsample_feat = F.interpolate(feat_high, scale_factor=2., mode='nearest')
inner_out = self.fpn_blocks[...](torch.concat([upsample_feat, feat_low], dim=1))
# bottom-up (PAN 방향)
downsample_feat = self.downsample_convs[idx](feat_low)
out = self.pan_blocks[idx](torch.concat([downsample_feat, feat_high], dim=1))
```

- **fusion block = `CSPRepLayer`**:

```python
# hybrid_encoder.py:88-112 (class CSPRepLayer)
self.conv1 = ConvNormLayer(in_channels, hidden_channels, 1, 1, ...)   # 1×1 conv
self.conv2 = ConvNormLayer(in_channels, hidden_channels, 1, 1, ...)   # 1×1 conv
self.bottlenecks = nn.Sequential(*[RepVggBlock(hidden_channels, hidden_channels, ...) for _ in range(num_blocks)])
self.conv3 = ConvNormLayer(hidden_channels, out_channels, 1, 1, ...) if ... else nn.Identity()
...
def forward(self, x):
    x_1 = self.conv1(x); x_1 = self.bottlenecks(x_1)
    x_2 = self.conv2(x)
    return self.conv3(x_1 + x_2)     # 두 경로의 element-wise add
```

  → 논문 Fig 5의 fusion block 구조(1×1 conv로 채널 조정 + N개 RepBlock + element-wise add)와 **정확히 대응**한다. `depth_mult=1`이라 N=3.

### 6.2 쿼리 선택 (논문 §4.3)

- **주의(문헌 차이, 정정 필요):** 이 v1 PyTorch 구현의 top-K 기준은 **분류 점수 단독**(`enc_outputs_class.max(-1).values`)이다. 논문이 "uncertainty-minimal query selection"이라 부르는 것은 (i) 선택 기준을 분류·위치의 **결정론 변수**로 다루고 (ii) 식 (2)~(3)으로 그 불확실성을 **명시 최적화**하는 *학습* 메커니즘이며, 공개 v1 코드는 그 학습 효과는 반영하되 선택 연산 자체는 분류 점수로 단순화되어 있다. **Q5-b 답변에서 "코드는 cls 점수, 논문은 불확실성"을 구분해 서술하는 것이 정확하다.**

### 6.3 RT-DETR의 손실 가중치 — 원문 DETR과 **다르다**

```yaml
# configs/rtdetr/include/rtdetr_r50vd.yml:67-78
SetCriterion:
  weight_dict: {loss_vfl: 1, loss_bbox: 5, loss_giou: 2,}   # classification이 VFL
  losses: ['vfl', 'boxes', ]
  alpha: 0.75
  gamma: 2.0
  matcher:
    type: HungarianMatcher
    weight_dict: {cost_class: 2, cost_bbox: 5, cost_giou: 2}  # class 2 (DETR는 1)
    alpha: 0.25
    gamma: 2.0
```

- **분류 손실이 CE가 아니라 VarFocal Loss**(`rtdetr_criterion.py:111` `loss_labels_vfl`)이고, **매칭 비용도 VarFocal 형태**로 계산된다:

```python
# matcher.py:89-91
neg_cost_class = (1 - self.alpha) * (out_prob**self.gamma) * (-(1 - out_prob + 1e-8).log())
pos_cost_class = self.alpha * ((1 - out_prob)**self.gamma) * (-(out_prob + 1e-8).log())
cost_class = pos_cost_class - neg_cost_class
```

  즉 RT-DETR는 DETR의 `−p̂` 대신 **focal 계열 비용**을 쓴다. 원문 DETR 논문(식 1)과의 차이이므로, "RT-DETR도 같은 매칭 비용을 쓴다"고 써서는 안 된다.
- **∅ 가중치도 다르다**: `rtdetr_criterion.py:32` — `eos_coef=1e-4`. DETR의 `0.1`(1/10)보다 **훨씬 강하게** no-object를 낮춘다. 300 슬롯 중 대부분이 ∅라는 점과 맞물린 강화 버전.

# 07 · 보충: RT-DETR 파이프라인 통째 데모 (`detr_pipeline_demo.py`)

> 스크립트: `day07_detr/detr_pipeline_demo.py` · 로그: `runs/detr_pipeline_stdout.txt` · 수치: `runs/detr_pipeline_metrics.json`
> **목적:** 오늘 다룬 RT-DETR 구조를 **백본부터 헝가리아 세트 손실까지 한 번에** 돌려 보고, "AIFI가 S5에만 붙는 이유 / 쿼리 선택이 무엇을 바꾸는지 / aux 헤드가 왜 있는"를 **숫자로** 확인한다.
> **환경:** 합성 데이터(128→64px 직사각형), CPU, 고정 시드 20261020, 학습 80 epoch × 2런.

---

## 1. 구현한 파이프라인 (논문 → 코드 대응)

```
input (B,3,64,64)
 └ Backbone  : 3단 CNN → S3(32ch,32²) · S4(64ch,16²) · S5(128ch,8²)          ← DETR §3.2
 └ HybridEncoder
     ├ AIFI   : S5만 flatten(64 토큰) → self-attention → Reshape            ← RT §4.2 (D_S5)
     └ CCFF   : top-down FPN(upsample+concat+fusion) → bottom-up PAN        ← RT §4.2 (Fig 5)
                 fusion block = 1×1 conv 2갈래 + bottleneck + element-wise add
 └ 후보 위치  : 3스케일 concat → N = 32²+16²+8² = 1344개 피처               ← RT §4.3
 └ 쿼리 선택  : 분류 점수 top-K(K=30) → content(피처) + position(예측 박스)  ← RT §4.3
 └ Decoder    : 6층(self-attn over 쿼리 + cross-attn to 1344 메모리)          ← RT §4.4
                 각 층마다 보조 예측 헤드(aux loss) → 5개 aux 출력
 └ 손실       : 헝가리아 매칭(비용 2·class + 5·L1 + 2·GIoU) → 세트 손실      ← DETR §3.1
                 ∅ 하향 10 (eos_coef=0.1) · L1×5 + GIoU×2 · 객체 수로 정규화
```

실측 텐서 흐름(`STEP 0` 출력):
```
backbone_S3_S4_S5      : [(2,32,32,32), (2,64,16,16), (2,128,8,8)]
AIFI_input_tokens(S5)  : (2, 64, 64)          # 8×8=64 토큰만 self-attention
CCFF_out_levels        : [(2,64,32,32), (2,64,16,16), (2,64,8,8)]
candidates_N           : 1344                  # 1024+256+64
selected_K             : 30
content_query          : (2,30,64)   position_query : (2,30,4)
aux_head_outputs       : 5          pred_logits : (2,30,4)   # 3클래스 + ∅
```

## 2. 두 가지 방식 비교 (동일 시드·데이터·스케줄)

| 항목 | vanilla (분류 점수 top-K) | uncertainty-minimal (U 항 추가) |
|---|---|---|
| AP@0.5 (val) | 0.760 | **0.791** |
| Prop cls (>0.5) | 0.037 | 0.099 |
| Prop both (cls & IoU >0.5) | 0.107 | 0.086 |
| 파라미터 | 0.43M | 0.43M |
| 학습 loss (최종) | 2.29 | 2.12 |

- **방향은 논문과 일치한다.** RT-DETR Table 4는 uncertainty-minimal이 AP +0.8을 얻었고, 이 미니 데모에서도 **AP가 0.760 → 0.791(+3.1)** 로 올랐다(합성 데이터라 절대값은 비교 불가, **방향성**만 유의).
- **U 항의 정의**: 논문의 $U=\|\mathcal P-\mathcal C\|$는 "위치 예측 분포와 분류 예측 분포 사이의 벡터 차"이다. 이 데모는 1차원 프록시 $U=\mathrm{relu}(\text{score}-\hat q)$ 를 쓴다. $\hat q$는 **IoU 헤드가 예측한 품질 점수**(Fig 6의 "IoU score")이며, 그감독 타깃은 "해당 후보 박스 vs best GT의 실제 IoU"다. 즉 **"확신은 큰데 위치가 나쁜" 구간만 벌린다.**
- **Prop both가 오히려 조금 내린 이유(정직한 보고)**: 이 지표는 임계값 0.5가 매우 엄격하고(선택 쿼리 30개 중 실제 매칭이 1~2개뿐), 학습 목표 자체가 달라지면 점수 분포가 함께 변한다. 즉 **이 미니 데모에서 Prop both는 두 방식의 차이를 안정적으로 가르는 지표가 아니었다.** AP 차이는 그럼에도 일관되게 나타났다(학습 로그에서 40~80 epoch 구간 반복 확인).

## 3. 디코더 깊이 (재학습 없이 속도 조절, RT-DETR Table 5 대응)

| 사용 층 | vanilla | uncertainty |
|---|---|---|
| 6층 | 0.760 | 0.791 |
| 5층 | 0.759 | 0.802 |
| 4층 | 0.752 | 0.794 |
| 3층 | 0.784 | 0.797 |
| 2층 | 0.789 | 0.786 |
| 1층 | 0.774 | 0.772 |

- **aux loss 덕분에 모든 층이 "사용 가능한 예측"**이다(학습된 층에서 멈추면 그 층의 헤드 결과를 그대로 쓴다). → RT-DETR이 재학습 없이 속도를 조절할 수 있다는 메커니즘이 **데모로 재현**됐다.
- **하지만 논문과 반대 방향이다**: 논문은 6층이 가장 좋고(53.1) 얕게 자르면 AP가 떨어진다(1층 49.1). 이 데모에서는 얕게 자를수록 오히려 AP가 비슷하거나 조금 좋다. 이유는 (a) 합성 데이터가 너무 쉬워 깊은 층이 과적합할 여지가 없고, (b) 쿼리 30개 vs 실제 객체 1~4개로 **깊을수록 남는 쿼리들이 노이즈를 학습**하며, (c) 각 층이 독립 supervision을 받는 구조라 얕은 층이 오히려 일반화가 빠른 것. **"깊은 게 낫다"는 결론은 실데이터·대규모·긴 스케줄 조건의 결과**라는 점을 이 데모가 다시 보여준다.

## 4. 실행 중 드러난 함정 3건 (구현 문서로 남긴다)

1. **GIoU는 원소별/쌍별 두 버전이 필요하다.** 처음에 원소별 구현만 두고 매칭 비용 행렬을 만들면 broadcasting이 (N,1)과 (N,)을 합쳐 (N,N) 비용 행렬이 되어 매칭이 완전히 깨진다(디버깅 중 IndexError로 드러남). → 쌍별 `giou_pairwise(N,4 × M,4) → (N,M)`와 원소별 `giou_loss_elem`을 분리했다. **논문 식 (10)은 "두 박스"에 대한 정의지만, 코드는 행렬 연산이 된다.**
2. **분류 헤드는 클래스 수 + 1이어야 한다.** DETR은 `class_embed`가 `num_classes + 1`개를 뽑아 ∅를 클래스로 쓴다(코드 `detr.py:37`). 처음에 C개만 뽑고 `cross_entropy`에 C+1 가중치를 줘서 타입 에러.
3. **인코더 헤퍼는 반드시 직접 감독해야 한다.** 이게 가장 중요했다. 인코더의 분류/박스 헤퍼에 손실이 없으면 **top-K 선택이 무의미**(랜덤 위치 선택)해져 파이프라인이 아예 학습되지 않았다(AP 0.00, loss 정체). RT-DETR의 criterion이 `enc_topk_logits`/`enc_topk_bboxes`를 손실에 포함시키는 이유가 바로 이것이다. → **선택된 top-K 슬롯에 디코더 매칭 결과를 되돌려** 인코더를 감독하고, **매칭 안 된 선택 슬롯은 ∅로** 감독(DETR 슬롯 규칙)했다. 후자가 빠지면 인코더 점수가 붕괴하면서 **U 항이 "점수를 낮추는 방향"으로 회피**했다(Prop cls 1.000 → 0.127, U ≈ 0.003).

## 5. 이 데모가 증명하는 것 / 증명하지 못하는 것

**증명함**
- 백본→하이브리드 인코더→쿼리 선택→디코더→헝가리아 세트 손실이 **끊김 없이 동작**한다(구현 난이도: 수백 줄, 커스텀 층 없음).
- AIFI를 S5에만 걸면 attention 토큰이 1344 → 64로 줄고(비용 $\propto$ 토큰²), 6장 05 자료의 "441배" 계산이 실제 구조와 맞는다.
- aux loss가 있으면 **모든 디코더 층이 독립적으로 유효한 예측기**가 되어, 재학습 없이 깊이를 조절할 수 있다.
- uncertainty 항을 넣으면(같은 시드·같은 스케줄에서) 최종 AP가 오른다.

**증명하지 못함(한계 명시)**
- 논문의 $U=\|\mathcal P-\mathcal C\|$는 **분포 간 거리**이고, 여기선 1차원 프록시다. 정밀 재현이 아니다.
- 합성 직사각형 데이터는 COCO가 아니다. 절대 수치 비교는 무의미하며 **방향성만** 유의한다.
- 성능 수치(AP@0.5) 자체는 DETR/RT-DETR 논문 수치와 비교 대상이 아니다.
- 멀티스케일 deformable attention(RT-DETRv2)·denoising query·NMS 제거는 이 데모 범위 밖이다(05 자료 §4 참조).

# Day 09 — 멀티뷰 카메라 3D 탐지: DETR3D → PETR → Sparse4D 조사 초안

> **성격: 조사(survey) 초안.** 이 문서의 모든 숫자는 원 논문의 표·초록 또는 공식 README에서 직접 확인한 **논문 내 수치**다.
> 우리 환경 재측정 수치는 하나도 없다. 결과 셀에는 반드시 조건(분할 · 백본 · 해상도 · GPU)을 붙인다.
> 기억에 의존했던 수치 중 아래 4개는 검증 실패로 **배제**했다(§6): DETR3D "46.2 mAP / 53.5 NDS", "GPU-center" 변형, Sparse4D "15.9 FPS", Sparse4D "no NMS" 명시.

## 1. 조사 목적과 범위

- **주제**: 카메라 전용 멀티뷰 3D 물체 탐지(nuScenes)에서 3D→2D 투영 방식의 세대 변화를 따라간다.
- **논문**: DETR3D (arXiv:2110.06922, CoRL 2021) → PETR (2203.05625, ECCV 2022) → PETRv2 (2206.01256, ICCV 2023, PETR 계보 참고) → Sparse4D (2211.10581, arXiv preprint) → Sparse4D v2 (2305.14018, arXiv preprint).
- **가설**: "Lift"를 어떻게 하느냐가 이 계열의 분수령이다. 명시적 투영 인덱싱 → 사전 연산 3D 위치 임베딩 → 앵커 중심 희소 샘플링 + 순환 전파.
- **측정 원칙**: 인용 수치 전용. 우리 CPU 규모 실험은 이번 주제(3D·멀티뷰·Transformer 대형 세계)에서 방향성 비교조차 안 한다.

## 2. 계보 한눈에 보기

| | DETR3D | PETR | PETRv2 | Sparse4D | Sparse4D v2 |
|---|---|---|---|---|---|
| 발표 | CoRL 2021 | ECCV 2022 | ICCV 2023 | arXiv 2022.11 | arXiv 2023.05 |
| Lift 방식 | 3D 쿼리 → 카메라 변환행렬로 2D 피처 인덱싱 | 3D 좌표 → MLP → **3D PE**를 피처에 합산 | 3D PE 확장으로 **시간 정렬** + 피처 유도 PE | 3D 앵커의 **4D 키포인트**를 뷰/스케일/시점별 샘플링 | 앵커를 **순환 전파**(ego motion 재투영) |
| 디코더 | 레이어마다 재투영 feature lifting | DETR식 전역 어텐션 **원샷** | PETR 유지 + 작업별 쿼리 | cascade 6 모듈 + **시간 융합(스택)** | 시간 융합 **재귀형 (O(T)→O(1))** |
| 시간 팔 | 단일 프레임 | 단일 프레임 | 2 프레임 | T 프레임 스택(T=1~9) | T 프레임 **순환** |
| test NDS (최고 구성) | 47.9 | 50.4 | 58.2 | 59.5 | **63.8** |
| test mAP (최고 구성) | 41.2 | 44.1 | 49.0 | 51.1 | **55.7** |

## 3. 논문별 핵심

### 3.1 DETR3D — `paper/detr3d` (arXiv:2110.06922 · [abs](https://arxiv.org/abs/2110.06922))

- **기구**: "sparse set of 3D object queries to index into these 2D features" — 3D 참조점을 카메라 변환행렬로 각 뷰에 투영(Eq. 2)해 멀티레벨 피처를 이중선형 샘플링하고, 가시 마스크 평균으로 쿼리 피처를 갱신. 레이어마다 재투영.
- **주장**: "We do not use any post-processing such as NMS during inference." (§4.1) — NMS-free 최초 명시.
- **한계 자인**: "Although our model avoids explicit depth prediction, depth estimation is still a core challenging in this problem." (§4.5)

| 구성 | 분할 | mAP | NDS | 근거 |
|---|---|---|---|---|
| R101+DCN, FCOS3D init † | val | 34.6 | 42.5 | 본문 Table 1 |
| R101+DCN, +CBGS # | val | 34.9 | 43.4 | 본문 Table 1 = README ✓ |
| **V2-99, DD3D init #** | **test** | **41.2** | **47.9** | 본문 Table 2 = README ✓ (상호검증: PETR/PETRv2/Sparse4D 비교표 전부 동일) |
| R50 / DLA34 † | val | 30.2 / 31.2 | 37.3 / 39.4 | 본문 Table 7 |

- FPS **미보고**. 학습만 "12 epochs on 8 RTX 3090, ~18 h" (§4.1).
- ⚠️ 비고: 공식 레포 `megvii-research/DETR3D`는 삭제됨(404). 현행 공식 = 으뜸저자 WangYueFt/detr3d.

### 3.2 PETR — `paper/petr` (arXiv:2203.05625 · [abs](https://arxiv.org/abs/2203.05625))

- **기구**: 3D 좌표 생성 → "sample 64 points along the depth axis following the **LID**" (§4.2, CaDDN 계승 — 내가 DETR3D에 잘못 귀속했던 깊이 축 샘플링은 **여기** 것이다) → MLP로 3D PE 변환 → 2D 피처에 합산 → 전역 어텐션 디코더. 레이어마다 재투영이 아니라 **한 번 정의된 PE**로 원샷.
- **헤드라인 수치의 조건**: "50.4% NDS and 44.1% mAP"은 **test 분할 + V2-99 + 외부 데이터** 구성이다(본문 Table 2. README엔 분할 표기가 없어 꼭 붙여야 한다).

| 구성 | 분할 | mAP | NDS |
|---|---|---|---|
| R101, 1408×512 | val | 35.7 | 42.1 |
| R101, FCOS3D † 1600×900 | val | 37.0 | 44.2 |
| R101 | test | 39.1 | 45.5 |
| **V2-99 \*** | **test** | **44.1** | **50.4** |

- **FPS 조건부**: 같은 입력(1056×384)에서 PETR **10.7 FPS**(Tesla V100) vs BEVDet 4.2 FPS — 단 BEVDet은 더 강한 3090. 논문 자체가 교차-GPU 비교임을 명시(§4.4).

### 3.3 PETRv2 — PETR 계보의 시간 확장 (arXiv:2206.01256 · ICCV 2023 [CVF](https://openaccess.thecvf.com/content/ICCV2023/html/Liu_PETRv2_A_Unified_Framework_for_3D_Perception_from_Multi-Camera_Images_ICCV_2023_paper.html) · DOI 10.1109/iccv51070.2023.00302)

- **기구**: 3D PE로 **프레임 간 물체 위치 정렬**, feature-guided position encoder, 작업별 쿼리(BEV seg / 3D lane 확장).
- val R50 800×320: 35.0/45.6 · val R101 1600×640: 42.1/52.4 · test R101: 45.6/55.3 · **test V2-99: 49.0/58.2** · test V2-99 ms: 50.8/59.1 (README 뉴스 날짜와 일치 ✓)
- FPS 미보고(논문·README 모두). 학습: 24 epochs, A100 8장, batch 8. TTA 없음.

### 3.4 Sparse4D v1 — `paper/sparse4d` (arXiv:2211.10581 · [abs](https://arxiv.org/abs/2211.10581))

- **기구**: 각 3D 앵커에 **다중 4D 키포인트**(고정 7 + 학습 6)를 뷰/스케일/시점별 피처에 투영·샘플링 → 뷰/스케일/시간/키포인트 **계층 융합**; **instance-level depth reweight module**로 3D→2D 투영의 ill-posed 완화(초록). 앵커 초기화는 학습셋 **K-Means**(900 앵커, 6 cascade, 640×1600, R101) (§4.2).
- ⚠️ "depth sort" 같은 기구는 없다. 깊이 메커니즘은 depth reweight(v1)·dense depth supervision(v2).

| 구성 | 분할 | mAP | NDS | FPS |
|---|---|---|---|---|
| T=1 | val | 38.2 | 45.1 | — |
| T=4 | val | 43.6 | 54.1 | — |
| T=9(−6) | val | 44.5 | 54.7 | — |
| **Vov-99, test** | **test** | **51.1** | **59.5** | — |
| 릴리즈 체크포인트 (R101+FCOS3D, 640×1600) | val | 0.4409 | 0.5438 | 2.9 (8× RTX 3090 환경 표기) |

- FPS 조건부(v2 본문 Table 1, 704×256·R50·RTX 3090): T=1 **21.5** → T=2 15.3 → T=3 12.6 → T=5 9.0 → T=7 7.1 → T=9 6.1, GPU 메모리 424→1149 MB. **프레임 스택 규모와 FPS·메모리가 동선형으로 비싸다**는 것 자체가 v2 동기.
- 레포: linxuewu/Sparse4D → 2024-01-22 HorizonRobotics/Sparse4D 이관.

### 3.5 Sparse4D v2 — `paper/sparse4d_v2` (arXiv:2305.14018 · [abs](https://arxiv.org/abs/2305.14018))

- **기구**: 순환형 다중 프레임 피처 샘플링. 이전 프레임 인스턴스를 ego motion으로 현재 프레임 앵커에 재투영, 앵커 인코더로 PE 재계산(§3.2). "reduces the computational complexity of temporal fusion from **O(T) to O(1)**" (초록). 신규 물체는 단일 프레임·단일 레이어 디코더로 발굴 후 상위 점수 인스턴스만 전파.
- ⚠️ "no NMS" 문구는 v1/v2 논문 어디에도 없다(NMS-free 명시는 DETR3D가 유일). 인용 불가.

| 구성 | 분할 | mAP | NDS | FPS |
|---|---|---|---|---|
| R50, 256×704 | val | 43.9 | 53.9 | **20.3** |
| R101, 512×1408 | val | 48.5 | 58.0 | 8.4 |
| R101 + nuImage 사전학습 † | val | 50.5 | 59.4 | 8.4 |
| † + 미래 프레임 \* | val | 52.1 | 60.8 | 7.1 |
| **Vov-99, 640×1600** | **test** | **55.7** | **63.8** | — |

- **속도 메커니즘이 성과로 이어진 지점**: EDA 도입 후 FPS 13.7→**20.3**, 추론 GPU 메모리 −53%, 학습 메모리 6328→3100 MB, 총 학습 23.5 h→14.5 h (본문 Table 2, RTX 3090·batch 1).
- 문맥상 v1 대비 test +4.3 NDS (59.5→63.8) — 조건(Vov-99·640×1600 공통)에서.

## 5. 서사 정리 (포스터 논지)

1. **DETR3D**: 쿼리 기반 set prediction을 3D로 들고 온 첫 두 걸음. 투행은 명시적(변환행렬), 디코더는 NMS-free. 깊이 애매성 본인 인정.
2. **PETR**: 재투영을 버리는 전략 — 3D 좌표를 한 번 PE로 바꿔 피처에 쳐 넣고 전역 어텐션 원샷. 비용이 디코더에서 임베딩 전처리로 이동.
3. **PETRv2**: PE가 시간 정렬까지 흡수. 2 프레임.
4. **Sparse4D**: PE schooling과 반대편 — 앵커 기준 4D 키포인트 희소 샘플링. 시간은 스택(T 늘리면 FPS·메모리 비례 증가).
5. **Sparse4D v2**: 스택 압박을 순환으로 해소 — 인스턴스 상태/피처만 프레임 간 전달, O(T)→O(1), FPS 2.9→8.4(R101급)/20.3(R50급), test NDS 63.8.

## 7. Scope (이번 일에 안 한 것)

- nuScenes 리더보드 실측 재현 없음(인용 전용 원칙에서 자제). FPS는 회사 환경 조건만 기록.
- 시각화 차트 일체 미제작 — 이 문서와 포스터는 표·문만으로 이미 3D 공간을 축실했다. 그림은 다음 세션에서.
- BEVFormer(시기상의 주요 대안 계열), StreamPETR/SparseBEV 등 후속 — 범위 밖(포스터 "Next" 카드 대상).

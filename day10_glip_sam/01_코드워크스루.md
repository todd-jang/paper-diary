# Day 10 · 01 — 코드워크스루: GLIP이 "탐지"를 말로 바꾸는 법, SAM이 "분할"을 프롬프트로 여는 법

> **원칙**: 모든 수치는 `00_검증팩트시트.md`의 검증 셀만 사용. 우리 재측정이라면 별도 표기.
> 본 문서는 코드 순서로 구조를 뜯어본다: GLIP(분류기를 로짓 바꾸기 하나로 grounding 모델로 만든다) → SAM(프롬프트 인코더 + 디코더로 "어떤 프롬프트나 분할"을 노린다).

## 1. GLIP — 로짓 스왑 하나로 여는 오픈-세계

### 1.1 통상 탐지 모델과 딱 한 조각만 다르다
GLIP §3.1의 핵심 문장:

> "Any object detection model can be converted to a grounding model by **replacing the object classification logits** in its box classifier with the **word-region alignment scores**, i.e., dot product of the region (or box) visual features and the token (or phrase) language features."

- 원래: `S_cls = O Wᵀ` (O: 리전 피처 N×D, W: 클래스 임베딩 C×D → 점수 N×C)
- GLIP: `W` 대신 **프롬프트 텍스트를 인코딩한 토큰 피처** `P = Enc_L(Prompt)` (M×D) → `S_ground = O Pᵀ` (N×M)
- 로스 구조는 그대로(focal/binary). 변한 것은 **분류기 가중치만 "문맥화된 말"로 교체**된 것.

**결과(Table 2, zero-shot COCO 2017val)**:
- GLIP-T (A): **42.9** → GLIP-T (B): **44.9** (같은 데이터 — 딥퓨전의 효과 +2.0)
- GLIP-T (C): **46.7** (O365+GoldG) → 목표: **모델 구조는 그대로, 분류기만 "열린 세계 문장"**

### 1.2 프롬프트 = "클래스 목록을 자연어로"
> §3.1: `Prompt = "Detect: person, bicycle, car, ..., toothbrush"` — 각 클래스 이름이 grounding 후보 phrase.

- **경험칙 (§3.1 명시)**: BERT 초기화를 쓰면 `person. bicycle. car. ...` 식 **온점 나열 프롬프트**가 인간 친화형 프롬프트보다 낫다.
- 레포 설정(glip_Swin_T_O365_GoldG.yaml): 분리자 `". "`, 프롬프트당 카테고리 **85개** 샘플링, 입력 **256 토큰** 제한(App. §C.1) — "프롬프트 용량"이 하이퍼파라미터라는 관점.
- 1,200 클래스 LVIS면 **40개/프롬프트 청크** 처리(App. §C.2).

### 1.3 딥 퓨전 — 말이 이미지에 스며드는 3식
이미지 = **Swin Transformer + Dynamic Head(DyHead)**, 언어 = **BERT(base-uncased)** + **신규 추가 BERTLayer**.

```
i ∈ {0..L-1} 에 대해:
  O^{t2i}_i, P^{i2t}_i = X-MHA(O_i, P_i)      # 교차 모달 multi-head attention (Eq. 4)
  O_{i+1} = DyHeadModule(O_i + O^{t2i}_i)     # 말이 이미지로 (컨텍스트 벡터, Eq. 5)
  P_{i+1} = BERTLayer(P_i + P^{i2t}_i)        # 이미지가 말로 (Eq. 6)
```

> §3.2: "*BERTLayer is newly-added BERT Layers on top of the pre-trained BERT... cross-modality communication is achieved by the cross-modality multi-head attention module (X-MHA)*"

- 소거(Table 8, O365 단독 학습): 딥퓨전 ✗→✓ 시 COCO 42.9→44.9, **ODinW zero-shot 28.7→33.2** — 저성능 백본이 아니라 "우리 도메인 단어"가 스며드는 효과.
- 레포 설정: `EARLY_FUSE_ON: True`, `TYPE: "MHA-B"` — **말 토큰 피처가 모든 DyHead 레이어에 "추가 문맥 백터"로 여입** (없으면 late-fusion).

### 1.4 학습 타겟은 "토큰"까지 내려간다
- phrase 단위 타겟 T(N×c의 0/1) → **sub-word 레벨 T′**로 확장: 긍정 phrase의 모든 sub-word = 긍정, 추가 토큰·[NoObj] = 부정 (§3.1)
- 추론: "**토큰 확률의 평균 = phrase 확률**" (`SCORE_AGG: "MEAN"`), 후보 선택 `TOPK=9`
- Day 07 DETR 비교: DETR은 "쿼리=100 슬롯의 헝가리안 1:1", GLIP은 "리전=N × 토큰=M의 정렬 행렬" — 타겟이 사라지고 문장이 온다.

### 1.5 사전학습의 핵심 — "grounding 데이터가 이긴다"
- 검출 데이터만 키우기: FourODs(2.66M 검출, >1,500클래스) → COCO 46.3 · LVIS minival APr **15.0** (Table 5)
- **grounding 추가**: O365+GoldG → COCO **46.7** · LVIS APr **17.7**
- 웹캡션까지: GLIP-T(O365,GoldG,Cap4M) → LVIS APr **20.8** — §4.4: "*image-text data further widens the gap on LVIS AP_r (20.8 versus 15.0)*"
- 스케일: 초록 **27M grounding 데이터 = 3M 사람 검수 + 24M 웹쌍** (pseudo phrase-box 78.1M, 고유 명 58.4M) — 검출 데이터(≤2,000 카테고리)와 비교하면 phrase 어휘(Flickr30K 44,518 + VG 110,689)가 지배한다.

### 1.6 읽고 나면 남는 것
- GLIP-L(COCO-free) **zero-shot COCO 49.8** — 리더보드 모델이 아닌 **"문장만 바꾸는"** 모델이 49.8.
- 가장 강력한 실전 수치는 ODinW: **zero-shot 52.1 ≈ 10-shot supervised 50.8** (Table 11), 프롬프트 튜닝만으로 **67.9** (full tuning 68.9 대비 1.0 AP 차, Tables 12–13) — 신세계 적응 비용이 프롬프트 하나로 떨어진다.
- Day 07–08 연결: RT-DETR까지 후보는 "**학습된 클래스 목록**"이었고 GLIP부터는 "**문장**"이 된다.

## 2. SAM — "어떤 프롬프트나 분할"을 3요소에 분산

### 2.1 과제 정의 (§2)
> "*the promptable segmentation task, then, is to return a valid segmentation mask given any prompt. The requirement of a 'valid' mask simply means that even when a prompt is ambiguous ..., the output should be a reasonable mask for **at least one** of those objects.*"

- 프롬프트 유형: 전경/배경 점 · 박스 · 마스크 · **자유 텍스트(= CLIP 텍스트 인코더 차용)**
- 훈련 = "프롬프트 시퀀스 시뮬레이션": 샘플마다 점·박스·마스크 프롬프트를 순차 입력

### 2.2 구조 3요소 (§3 + App. §A)
1. **이미지 인코더**: *"MAE pre-trained ViT... **ViT-H/16** with **14×14 windowed attention** and **four equally-spaced global attention blocks**"* — 입력 **1024×1024**(짧은 변 패딩), 임베딩 **64×64** → 1×1 conv 256ch → 3×3 conv 256ch
2. **프롬프트 인코더**: 점/박스 = 위치인코딩 + 타입 임베딩(**256d**), 텍스트 = **CLIP 텍스트 인코더**, dense 마스크 프롬프트 = conv 체인(4→16→256ch)
3. **마스크 디코더**: *"*modified Transformer decoder block**" — **2층**(dim 256, MLP 2048, **8 heads**, dropout 0.1), 셀프어텐션(프롬프트) + **양방향 크로스어텐션**(프롬프트↔이미지), 4× 전치 conv 상향샘플, 마지막 **MLP 출력 토큰 = 동적 선형 분류기** → 패치 레벨 로짓

> 효율성(§3): "*the prompt encoder and mask decoder run in a web browser, on CPU, in ~50 ms*" — 조건 중요(아래 실습 참고).

### 2.3 애매성 설계 — "3개 답하되, 최손값만 저백프로프"
> §3: 3개 후보 마스크(whole / part / subpart) → 학습 시 **손실 최소값만** 백프로프 · 랭킹은 **estimated IoU** 토큰 · 조합 손실은 **focal : dice = 20 : 1**(App. §A)

- **다중 프롬프트 예외(App. §A — 자주 오해되는 부분)**:
> "*we only predict a single mask when more than one prompt is given... This fourth mask is never returned for a single prompt and is the only mask returned for multiple prompts.*"

→ 즉 "SAM은 항상 3개"는 틀림: **단일 프롬프트일 때만 3개, 다중 프롬프트면 1개.**

### 2.4 진짜 발전은 "데이터 엔진" (§4 3단계 — Model-in-the-loop)

| 단계 | 방법 | 누적 | 마스크/이미지 | 세부 |
|---|---|---|---|---|
| 1 보조-수동 | 클릭 대화형 도구 | 120k 이미지 → **4.3M** | 20→44 | 시간/마스크 **34s→14s**, 6회 재학습(ViT-B→H 스케일업) |
| 2 반자동 | 박스 디텍터 사전채움 | +180k → **10.2M** | 44→72 | 5회 재학습 |
| 3 자동 | **32×32 점 그리드** + 20개 확대 crop | 11M 이미지 → **1.1B** | 평균 **~100** | 전체 99.1% 자동 |

- 품질 필터(App. §B): 예측 IoU **88.0** · 안정성(anchor -1/+1) IoU **95.0** · **box NMS 0.7** · <100px cc 제거
- 품질 증거(§5): "*94% of pairs have greater than 90% IoU*" vs 인간 상호 합의 85–91% — **자동 라벨이 "인간 합의" 수준이라는 정당화**
- 규모문(§5): "*400× more masks than any existing segmentation dataset*" · "*11× more images than Open Images*"

### 2.5 평가 — "거의 다 이기는데, edge에선 진다"
- **BSDS edge (Table 3, ODS/OIS/AP/R50)**: SAM **.768/.786/.794/.928** vs EDETR **.840/.858/.896/.930** — zero-shot 라벨 프리 edge는 미달 (조건: 16×16 점 그리드 → 768 마스크 후보(3/점), NMS 후 Sobel)
- **LVIS proposal (Table 4, AR@1000)**: SAM **59.3** vs ViTDet-H **63.0** — 전체는 열세이지만 **rare 65.8 vs 58.3은 이김** (open-world성 정당성)
- **인간 평가(LVIS v0.5 단일 점, Fig. 18)**: RITM **6.5** ← SAM-single **7.7** ← SAM(3개 중 선택) **8.1** ← GT **8.5** (10점 척도) — "사람 손 부담" 축에서는 거의 GT
- **인스턴스 분할(Table 5)**: ViTDet-H 박스 프롬프트 → zero-shot **COCO 46.5 / LVIS 44.7 AP** (완전 지도 항목 51.0/46.6)
- 속도 주의: 50ms는 **CPU·브라우저 · prompt encoder+mask decoder**만. "**SAM's overall performance is not real-time when using a heavy image encoder**"(§8) — ViT-H GPU 지연 수치는 어디에도 없음(배제 목록 §3).

## 3. 사상 연결 — GLIP : 분류기 = SAM : 마스크
- **둘 다 "지능을 경계에 두자"**: GLIP은 분류기 가중치 `W`를 말로 교체(후보 세계가 열림), SAM은 마스크 생성 규칙을 프롬프트에 위임(과제 세계가 열림).
- **"새로운 라벨 단위"의 발명**: GLIP의 phrase(27M grounding 데이터), SAM의 클릭(SA-1B 1.1B) — 기존 데이터셋 class가 아니라 **토큰/상호작용이 새 label**이 된다.
- open-world 증명이 tail에서 온다: GLIP LVIS APr 15.0→20.8(§4.4), SAM rare AR 65.8 — Day 12 CLIP("제로샷 시각-언어 정렬")으로 이어지는 브릿지.

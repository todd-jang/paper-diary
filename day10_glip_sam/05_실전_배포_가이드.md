## 1. GLIP — 경로 ① 공식 저장소 (`microsoft/GLIP`, 논문 재현용)

- **설정**: `configs/pretrain/glip_Swin_T_O365_GoldG.yaml` — GLIP-T의 데이터 레시피(O365+GoldG)가 그대로 이름이 된다. 사전학습 데이터 조합이 곧 성능(Table 5: O365+GoldG → COCO 46.7 vs 검출 데이터만 → 46.3).
- **사전학습 vs 파인튜닝**: zero-shot은 스왑 평가일 뿐(로짓 ↔ 프롬프트 임베딩, App. §B 동등성). 개인 데이터로 갈 때는 **프롬프트 튜닝**이 최저 비용 고성능 경로다 — Tables 12–13: linear probe 59.2 < 프롬프트 튜닝 67.9 < 초전체 튜닝 68.9(13-avg, GLIP-L).
- **ODinW few-shot 프로토콜**: 카테고리별 k-shot 이미지로 튜닝 → 평가. Table 11의 ±편차는 이 반복 시행에서 나온다.
- **프롬프트 문법**: 카테고리를 건네는 방식이 성능을 직접 바꾼다(Table 10: EgoHands 22.1→50.0 "hand of a person", Packages 50.0→72.3). 다만 Pothole 17.8→17.7처럼 **효과가 없는 사례도 공개되어 있다** — 만능 기법이 아니다.

### GLIP 대형 어휘 실전 지침 (App. §C)

1. **256 토큰 한도**: 프롬프트 인코더의 컨텍스트 제한. 초과 카테고리는 **나무래어도 안 된다**.
2. **40 categories per prompt**: 논문이 실제 쓴 청크 크기(LVIS 1,203 카테고리). 카테고리별로 정확히 1회씩 등장하도록 쪼개 스코어를 조인한다(실습 V4: coverage 1.0, 일치 1.0).
3. **비용**: 딥퓨전(O_t2i 여입)는 비퓨전 대비 FPS를 4.84→2.52로 깍아먹고 학습 메모리를 크게 올린다(Table 7: T 추론 2.52FPS/2.4GB, L 추론 0.32FPS/7.7GB — P100·batch 1, 해상도 미기재이므로 절대값 비교 금지). 배치 1을 유지해야 유이한 구조.

## 2. SAM — 경로 ① 공식 저장소 (`facebookresearch/segment-anything`)

- **체크포인트 3종**(공식): `sam_vit_h_4b8939.pth` 2,564.6MB / `sam_vit_l_0b3195.pth` 1,249.5MB / `sam_vit_b_01ec64.pth` 375.0MB. 이미지 인코더 기준 파라미터: ViT-B **91M** · ViT-L **308M** · ViT-H **636M**.
- **추론 구조 = 비용 구조**: 이미지 인코더(ViT-H, 1024×1024)는 **이미지당 1회**임베딩 64×64를 뽑고, 프롬프트 인코더+마스크 디코더는 **프롬프트마다** 돈다. 논문 보고 조건: **CPU·웹브라우저에서 디코더 쪽 ~50ms**(임베딩 사전계산), 마스크 디코더는 이미지 인코더 연산의 **1% 미만**.
- ⚠ **GPU 클릭당 지연 수치는 논문에 없다**. "not real-time when using a heavy image encoder"가 전부다(ViT-H가 무겁다는 뜻). 벤치마크 청구는 직접 측정해야 한다.
- **SatPredictor 사용 순서**(효율 핵심): `set_image()` 1회 → `set_image_embedding` 캐시 → `predict(points/box/mask)` 반복. 학습 90k 이터레이션 = 그 패턴을 **학습 시 확률로 흉내낸 것**과 동일 설계.
- **라이선스**: 코드·모델 **Apache 2.0** / SA-1B 데이터는 **별도 리서치 라이선스**(상업 이용 불가 확인 필요).

### SAM 설계상 주의점 (데모 03_실습 V1·V3·V4와 직결)

| 항목 | 내용 |
|---|---|
| ① "항상 3개" 금지 | 단일 프롬프트 → **3개**(whole/part/subpart), **2개 이상 프롬프트 → 1개**. 배포 후처리(RN Score 선택기)는 이 개수 차를 반영해야 한다 |
| ② 원본 코딩을 고르는 로직 | 논문은 **가장 낮은 손실**의 4번째(다중) 마스크를 학습시키고, 출력 랭킹은 **estimated IoU 토큰**이 방출하는 검사 필요 |
| ③ 손실 구성 | focal : dice = **20:1** — dice 항에 구조를 맡기고, focal에 경계 신뢰도(YoU 예측 학습)를 맡기는 조합. focal 단독은 포화로 붕괴(실습 V4: 0/3) |
| ④ MAE 프리트레인 | 이미지 인코더는 MAE 사전학습 ViT-H/16 + **windowed attention 14×14 + 전체 attention 4 블록** — 전역 어텐션 비용은 4회에만 낸다 |
| ⑤ 학습 비용 | **256×A100·68시간**(~6963kWh, CO₂e 2.8t) — 제로베이스 재현은 아니고 **사용자**로 접근하는 게 실전 경로 |

## 3. 두 모델의 선택 가이드

| 상황 | 선택その 이유 |
|---|---|
| **단어 단위 카테고리 탐지 + 박스**가 필요 | GLIP — 문장을 그대로 준다. 큰 어휘는 청킹 필수 |
| **박스는 있는데 마스크·라벨이 없다** | SAM — 박스/점 프롬프트만으로 학급 시스템 없이 마스크 획득(동적 마스크 파이프라인 = 데이터 엔진 Fig. 6과 같은 원리를 개인 데이터에 적용) |
| **"Sorting" 카테고리가 내부 전문 용어라면...** | GLIP — 카테고리 뜻이 텍스트 임베딩에 실려 있어야 하므로, 의미zxz 기재(Table 10 방법 참조) 후 평가가 필요. 효과 없을수도(Pothole 사례) |
| 대량 자동 라벨링 | SAM 자동 모드 → 정수화(**99.1% 자동 생성**) → 심층 검증을 위해 인간이 다시 소량만 (모델 재측정 94% pairs IoU>90% 배경 지식) |
| 폭넓은 화면·실시간 | GLIP-L(0.32 FPS)도 SAM ViT-H 인코더도 부실히 — 인코더를 ViT-B(91M)로 내리는 게 1차 대응(SAM 소거) + ⚠ 마찬가지로 GPU 지연 수치는 자체 측정 |

## 5. 오늘 실습(03_실습)과의 연결

- 실습 V1·V2가 보인 "토큰 평균의 분산 감소 + 로짓 스왑 등가성"이 **① zero-shot이 왜 되는지**의 근거이고, README/논문 수치가 흔들리지 않는 이유(스왑은 등가 변환)다.
- 실습 V3의 "조준된 어텐션만 early fusion 이득(무학습 softmax는 역효과)"은 **GLIP 딥퓨전 비용(Table 7)을 치르고도 얻는 것**이 정확히 무엇인지의 구조적 답이다.
- 실습 V4(SAM)의 "focal 단독 붕괴"는 **focal+dice 20:1이라는 논문 조합의 필요성**을 보여주며, 배포해 결國 디코더 손실을 조정할 일이 있으면 dice 비중을 늘리는 방향이 검증된다.
- 데이터 엔진 차트(`runs/figures/03_sam_data_engine.png`)는 **라벨 파이프라인이 원동력**이라는 문장의 시각 증거: 4.3M → 10.2M → 1.1B, 99.1% 자동.

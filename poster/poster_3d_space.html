3D Detection

DETR3D → PETR → Sparse4D: three ways to lift multi-view 2D features into 3D space — explicit projection, precomputed position embedding, anchor-centric sparse propagation.

Central claim — the fork in this lineage is the lift. DETR3D re-projects at every decoder layer, PETR folds 3D coordinates into a position embedding once, Sparse4D moves the lift onto anchors and keeps it alive across frames — O(T) stacking becomes O(1) recurrence.

A sparse set of 3D object queries is projected into each camera view via the transform matrix (Eq. 2), then features are bilinearly sampled; predictions use a set-to-set loss.

03 · PETRKill the re-projection: 3D position embedding

Sample 64 points along the depth axis (LID, §4.2 — this depth mechanism belongs to PETR, not DETR3D). An MLP turns 3D coordinates into a 3D PE, added to image features: "3D position-aware features".

The decoder is then a standard DETR global-attention pass over the flattened map — one shot, no per-layer projection. The lift cost moved from the decoder loop to a preprocessing step.

04 · PETRv2The embedding learns to align time

The same 3D PE is extended for temporal alignment of object positions across frames, plus a feature-guided position encoder and task-specific queries (multi-task: BEV segmentation, 3D lane).

val R1011600×640: 42.1 / 52.4   test V2-9949.0 / 58.2   ms50.8 / 59.1

2 frames is all it needs — yet it already beats Sparse4D's 9-frame val numbers on the test split. Venue verified in CVF: ICCV 2023, DOI 10.1109/iccv51070.2023.00302.

alignment moved from warping pixels to warping queries

05 · Sparse4DAnchors that look: 4D keypoints + depth reweight

Each 3D anchor carries multiple 4D keypoints (7 fixed + 6 learnable) projected to every view / scale / timestamp; features are fused hierarchically across views, scales, times, keypoints.

depthan instance-level depth reweight module eases the ill-posed 3D→2D projection (abstract). initK-Means on the training set: 900 anchors, 6 cascades, 640×1600.

06 · Sparse4D v2Stack → recurrence: O(T) to O(1)

In v1, temporal fusion stacks T frames — FPS falls 21.5 → 6.1 as T: 1→9 (v2 paper Table 1, R50·704×256·3090). v2 instead propagates instances: previous-frame outputs become current-frame anchors via ego motion, re-encoded each frame.
